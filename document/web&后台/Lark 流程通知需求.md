# Lark 流程通知需求

## 通知原则

- Lark 只负责待办提醒、关键节点进度和审核结果通知。

- 所有审核、修改、发布操作仍在消息中心后台完成。

- 当前处理人收到待办通知，创建人及负责人收到关键结果通知。

- 内容必须先审核通过，才能进入多语言流程。

- 不通知每一次细微进度变化，避免消息轰炸。

- 发起人不能审核自己提交的内容。

---

## 总体通知流程

```Plain Text
提交内容审核
  → 通知内容审核人
  → 内容审核通过
  → 通知创建人/负责人
  → 创建外部机翻任务
  → 机翻返回
  → 通知对应语言审核人
  → 所有语言审核通过
  → 通知创建人/负责人
  → 进入发布或任务配置审核
  → 通知任务审核人
  → 任务审核通过
  → 通知创建人/负责人
  → 到达发送时间
  → 通知创建人/负责人开始发送
  → 发送完成
  → 通知创建人/负责人发送结果
```

---

## 审核任务分配

### 3\.1 内容及任务审核

- 从具备“审核中心写权限”的人员中随机选择一人。

- 发起人不参与自己提交内容的审核分配。

- 一个审核工单同一时间只分配给一名审核人。

- 审核人失去权限后，系统重新分配给其他审核人。

- 重新分配后通知新审核人。

- 创建人收到审核人变更通知。

### 3\.2 多语言审核

- 每个目标语言形成一个独立审核项。

- 普通语言分配给有多语言审核权限的人员。

- 小语种只能分配给拥有该语言审核权限的人员。

- 一个语言审核项同一时间只分配给一名审核人。

- 审核人失去语言权限后，系统重新分配。

- 发起人不能审核自己提交的译文。

# 人工消息模板流程通知

```Plain Text
提交内容审核
  → 内容审核人收到待办
  → 内容审核通过
      → 创建人收到通过通知
      → 有目标语言：进入机翻
      → 无目标语言：进入发布
  → 机翻返回
      → 各语言审核人收到待办
  → 所有语言审核通过
      → 创建人/负责人收到完成通知
      → 模板发布
  → 创建人/负责人收到发布成功通知
```

```Plain Text
  → 审核通过
  → 通知创建人/负责人

  → 到达发送时间

  → 通知发送结果
```

```Plain Text
任务名称

目标用户
预估人数
```

# 审核催办通知

超过 SLA 后：

- 通知当前审核人。

- 同时通知创建人或负责人。

- 不自动通过或驳回审核。

- 审核人失去权限时，重新分配后停止向原审核人催办。

# 通知去重

每条流程通知使用以下幂等键：

```Plain Text
lark:{object_type}:{object_id}:{workflow_stage}:{transition_version}:{recipient_id}
```

同一个幂等键只发送一次。

以下进度不发送 Lark：

- 机翻接口正常轮询状态。

- 单个用户的送达状态。

- 单个设备的 Push 状态。

- 发送过程中每次百分比变化。

- 审核页面中的普通保存操作。

- 同一流程节点未发生状态变化的重复更新。

任务发送只通知：

```Plain Text
开始发送
发送完成
任务审核结果
```

# 状态文案统一

内容已经审核通过并进入翻译流程后，Lark 不再显示笼统的“审核中”，统一显示“多语言审核中”。
