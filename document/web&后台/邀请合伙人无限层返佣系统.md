# 邀请合伙人无限层返佣系统

# 业务定义

## 1\.1 核心业务模型

**模型定义：无限级差佣金制**

- 平台为每个一级合伙人设定一个返佣比例上限（运营可在权限后台配置，当前原型演示为 **80%**），该比例即为此合伙人整条业务线的「总佣金包」上限参考。

- 合伙人可以无限层级地发展下级合伙人（平台对**新增发展**设有最多 **10 层**合伙人层级限制，见 §1.4），每一级合伙人的返佣比例由其直属上级设定，且**不得超过**上级自身的比例。

- **级差与合规**：上下级比例**允许相等**（级差 = 0，该上级在该笔交易上级差为 0，属正常配置）。仅当 `下级返佣比例 > 上级返佣比例` 时判定为**倒挂异常**（见 §1.4）。

- 当终端用户（直客或合伙人自营）产生交易手续费时，系统沿邀请链路向上逐级计算级差佣金，直到一级合伙人为止。

**角色定义**

|角色|账号类型|交易时身份|是否参与返佣分配|
|---|---|---|---|
|一级合伙人|Agent|渠道/交易者|是，享受自返佣，并从下级合伙人的级差中获利|
|N级合伙人 \(N≥2\)|Agent|渠道/交易者|是，享受自返佣，并从直属下级合伙人的级差中获利|
|直客|Client|纯交易者|是，为上级合伙人贡献级差的「燃料」，自己不拿返佣|

**核心原则：合伙人自营也参与返佣**

- 合伙人用自己的合伙人账号交易，自己拿走自己返佣比例对应的佣金（自返佣）。

- 同时，他的所有上级依然按级差规则分钱。

## 1\.2 返佣计算规则

### 规则一：自返佣

- 触发条件：代理使用自己的代理账号进行交易并产生手续费。

- 计算：`该代理的返佣比例 × 该笔手续费`

- 拿到钱的人：该代理本人。

### 规则二：直客级差

- 触发条件：直客进行交易并产生手续费。

- 计算：

    - 直客的直属上级代理：拿走自己**全额**返佣比例对应的佣金。

    - 该上级的每一位上级：拿走 `(自己的返佣比例 - 直属下级代理的返佣比例)` 的级差部分。

- 如果上级与直属下级的比例相同，则该上级在这笔直客交易上级差为 0。

### 规则三：代理自营级差

- 触发条件：某代理用自己代理号交易产生手续费。

- 该代理自己先拿走自返佣（规则一）。

- 他的所有上级，按规则二的方式，从他身上计算级差，即 `(上级比例 - 该代理比例) × 该笔手续费`。

### **公式总结：**

- 对任意一笔交易：

    1. 确定交易发起人 `X`（可能是代理或直客）。

    2. 如果 `X` 是代理，`X` 获得 `比例_X × 手续费`。

    3. 沿着 `X` 的上级链路向上遍历，当前上级 `P`：

        - 如果 `P` 是 `X` 的直属上级，`P` 获得 `(比例_P - 比例_X) × 手续费`

        - 否则，`P` 获得 `(比例_P - 比例_直属下级) × 手续费`

    4. 直到一级代理停止。

## 1\.3 返佣结算流程

**整体流程：日结制**

1. **交易数据采集**：系统实时记录每一笔交易的手续费。

2. **每日结算触发**：每日 00:00 \(UTC\+8\)，系统对前一日 00:00:00 至 23:59:59 的所有交易进行结算。

3. **数据同步**：生成用于审查的对账 CSV 包（表 1–4，及建议一并导出的一级比例快照表 2a），进入风控审批队列。

4. **人工审查**：风控或运营人员登录后台「佣金对账与发放」页面，进行四步审计：

    - **总量对账**：用 Platform\_Summary 核对平台总手续费与总返佣预算。

    - **聚合校验**：用 Rebate\_Split\_Detail 的流水表通过 Excel 枢纽分析，反向汇总每个代理应得总金额。

    - **差异比对**：将汇总结果与 System\_Proposed\_Payout 做 VLOOKUP 比对，排查是否存在非零差异。

    - **穿透抽样**：随机抽检一个代理，验证其分账流水是否与 Affiliate\_Map 中的比例关系吻合。

5. **审批执行**：

    - **通过**：风控点击「审核通过并放款」，系统将最终实发金额执行发放。

    - **拒绝**：风控填写拒绝原因，该批次标记为「已拒绝」，打回重算。

6. **数据归档**：所有 CSV 文件和审批记录存档备查。

## 1\.4 返佣比例调整、关系迁移与异常配置保护

### 比例倒挂（级差异常）

- **比例调整触发检查**：当任何代理的返佣比例被调低时（平台调一级、上级调下级、或在返佣树内批量修改），系统必须实时检查该代理名下**所有直属下级**的返佣比例。

- **异常判定标准**：若存在 `下级返佣比例 > 上级返佣比例`，则判定为**配置异常（倒挂）**。

- **允许级差为 0**：`下级返佣比例 = 上级返佣比例` 时**不算异常**，仅该上级在相关交易上的级差为 0，结算与对账正常进行。

- **异常影响范围**：以发生倒挂的**该返佣分支**为起点（该上下级节点及其下级），从异常当下起暂停该分支的返佣结算。**并非**整棵一级合伙人树下所有分支停结；同一一级下其他正常分支继续结算。

- **异常状态标记**：该返佣分支上的合伙人标记为 `待修正返佣后计算`（一级根节点若仅部分分支异常，可显示 `部分分支异常`）。异常期间该分支交易额计入「异常暂停交易额」；「异常返佣线」为倒挂的上下级地址对数量（仅统计「下级 &gt; 上级」的对数）。

- **暂停期间不展示/不计算应发返佣**：比例倒挂导致暂停结算时，系统**尚未完成应发返佣计算**（因比例关系无效）；运营侧仅展示 **暂停结算交易额**、**暂停结算手续费**，修正比例并恢复结算后再按新比例重算应发返佣。

### 修正与恢复

- 运营需进入「合伙人管理」或「返佣关系树」，找到比例倒挂的下级，**将其比例调低至 ≤ 上级比例**（等于上级即可解除倒挂）。

- 一旦该合伙人名下所有直属下级比例均 **≤** 自身比例，系统自动解除异常标记，**立即恢复**结算资格。

- 恢复后，对异常期间未结算的交易用**修正后的新比例**重算佣金。发放方式分两类（见 §1.4 补发规则与 §2.6）：

    - 若原应结日所属批次**尚未放款**（`等待对账` 或 `已拒绝`）：不进入「修正返佣补发」；修正后在该批次重算或随新批次正常实发。

    - 若原应结日所属批次**已审核通过并放款**：未实发部分进入「修正返佣补发」，按**原应结日**挂账，在后续某发放日补发。

### 运营权限上限与审批

- 每位市场运营在权限配置中设有 **一级合伙人返佣比例上限（%）**（原型演示为 **80%**），页面顶栏展示「权限上限: XX%」。

- **≤ 运营上限** 的比例调整：在返佣树内提交后**立即生效**（无需审批）。

- **&gt; 运营上限** 的一级绑定或比例调整：须提交审批，流程为 **市场运营提交 → 风控审核 → 老板审批**（风控通过后同步 Lark，老板可在 Lark 或后台通过）。

- **同一批提交中若混合「权限内」与「超上限」修改**：仅超上限项进入审批；权限内修改**自动放弃**（输入框回滚），须先处理超上限申请。

### 返佣关系迁移

- 运营可将某用户（普通用户或代理用户）及其伞下关系整体迁移到新的上级合伙人之下，并重新设定迁移主体的返佣比例。

- 迁移后须满足：迁移比例 ≤ 目标上级比例、≤ 运营上限、且迁移后整伞内任意父子节点满足「下级 ≤ 上级」（允许级差为 0；禁止下级 &gt; 上级）。

- 若迁移主体为代理用户，其原有下级树中若存在**深层倒挂**（下级 &gt; 上级，与本次迁移比例无关的历史问题），须在预览树中先修正再允许提交。

- 迁移申请提交后进入 **风控审核**（无需老板审批）；通过后执行关系变更。

- **迁移后的数据统计与返佣归属**见 §1.4「迁移后的返佣计算与业绩统计」。

### 合伙人层级上限（10 层）与迁移

- 平台对合伙人账号设置**最多 10 层**合伙人层级（L1 为一级合伙人，向下至多 10 层合伙人节点）。

- **用户端（合伙人中心）**：合伙人**新增下级合伙人**时，若会导致链路深度超过 10 层，系统**禁止绑定**新下级。该限制约束的是**新增发展**，不自动裁切已存在的深层节点。

- **迁移返佣关系**：迁移可能使某条业务链在系统内的**实际深度超过 10 层**（例如将较深整伞挂到较浅的上级之下）。迁移完成后：

    - **已存在的深层合伙人节点及其关系保留**，返佣与结算按新关系继续计算；

    - **不因迁移而作废 10 层限制**——限制仍作用于**迁移之后的新增下级**；处于第 10 层及更深处的合伙人，在合伙人中心**不可再发展新的下级合伙人**（与「用户层不允许延续新的下级」一致）。

    - 直客绑定、交易、返佣计算不受「10 层」约束（直客不计入合伙人层数）。

### 迁移后的返佣计算与业绩统计

迁移风控审核通过并生效后，返佣计算**立即**按**新的上级关系**与**新的返佣比例**执行。

**统一规则（不论迁移前正常或异常）**：

| 维度 | 规则 |
|---|---|
| 原上级 | 迁移生效后，该伞**不再累计**新的交易额、手续费、返佣贡献；历史已归属数据保留 |
| 新上级 | 迁移生效后，该伞的业绩与返佣贡献从 **0 重新累计**（周期统计不继承原上级下的数字） |
| 返佣计算 | 生效后按新关系与新比例统计、分账 |

**异常伞迁移的补充**：

- 若迁移前存在倒挂 / `待修正返佣后计算`，迁移至新上级后须在预览或返佣树内**修正比例**。

- 异常期间暂停的交易额、手续费及应计返佣，在修正完成并恢复结算后，**归属到新上级**维度统计与发放（不再挂原上级）。

- 若异常期间涉及**已放款批次**的欠发部分，按 §1.4 补发规则以**原应结日**进入「修正返佣补发」；主体已在新上级伞下。

**说明**：普通用户迁移仅变更邀请关系；代理用户为**整伞迁移**，伞内全部合伙人节点与直客一并变更上级。

## 1\.5 其他补充

### **活跃用户 / 活跃代理定义**

- 定义为「所选时间周期内，交易额 &gt; 0 的用户或代理」。

- 此指标为**查询时实时计算**，不需要数据落库，不需要维护每日活跃状态表。

- 举例：选择统计周期为「1W」，则统计近 7 天内有过至少一笔交易（交易额 &gt; 0）的用户/代理数量。

- **用户合伙人中心「用户规模」展示口径**：主行展示**交易用户**数（周期内交易额 &gt; 0）；次行灰色小字展示**总用户**数（注册或归属伞内总人数，含未交易者）。

### **用户侧佣金与状态展示规则（合伙人中心）**

以下规则仅描述**合伙人登录后**在「佣金结算与发放」及「合伙人管理」中的展示逻辑，与后台批次状态、风控操作对应关系如下：

| 后台 / 系统事实 | 用户侧展示 |
|---|---|
| 当日批次**等待对账**，佣金尚未放款 | **待结算** |
| 当日批次**已审核通过并放款** | **已结算** |
| 当日批次**已拒绝**（打回重算） | 仍展示 **待结算**（不向用户暴露「已拒绝」） |
| 存在**返佣树异常**或**直属下级比例倒挂**，该日相关交易额暂停计入可发返佣 | **返佣异常停止结算**；**交易额有值，返佣金额为 0** |
| 风控对某合伙人**人工调减实发**后 | 「每日结算流水」中**返佣金额**按**修正后实发**展示；「合伙人管理」中**总返佣收入（本期预估）**等同口径，按修正后累计展示 |
| 存在**违规扣减** | 返佣金额主行展示实发/应发净值；次行红色小字 **违规 −$XX** 展示扣减额 |

**返佣异常停止结算**与后台「待修正返佣后计算」的对应关系：

- **直属下级比例倒挂**（仅一层：`直属下级比例 &gt; 我`）：影响该直属下级及其伞；用户在该下级行看到倒挂预警，贡献级差收入暂停。
- **团队返佣树异常**（深层链路中存在 `下级 &gt; 上级`，但不一定是我与直属下级之间）：用户自身或下级行展示异常条数、暂停结算交易额；弹窗可查看每条异常返佣线及**该线停止结算交易额**。

### **净收入（后台指标）**

- 对任意查询根节点（某一级或下级合伙人）：`净收入 = 该伞下净手续费 − 由该伞下交易触发的全部返佣支出`。

- 「全部返佣」包含分给伞内所有合伙人，以及分给伞外上级合伙人的级差（因这些级差均由伞下交易手续费产生）。

- 一级合伙人视角即整条业务线平台留存；下级合伙人视角为「以该合伙人为根的子树」对平台整体的净贡献。

# 后台管理：合伙人管理及结算对账

本后台面向两类内部人员：

- **运营/BD 同学**：负责配置和管理一级合伙人、调整返佣树比例、发起关系迁移（仅可见自己负责的数据）。

- **超级管理员 / 风控**：负责维护后台人员与页面权限（含一级合伙人返佣比例上限，见《[后台权限与角色管理](后台权限与角色管理.md)》），执行合伙人相关审批，以及每日佣金对账与发放。

## 通用交互约定

### 统计周期

列表页与详情页均提供统计周期切换：**1D / 1W / 1M / 3M / ALL**（默认 ALL）。切换后，团队总交易额、手续费、返佣、净收入等周期敏感指标同步刷新。列表与详情打开时默认继承列表当前周期。

### 分页

合伙人列表、详情子表、返佣树一级支路、迁移预览树、结算批次与明细、操作记录、审批列表等长列表统一 **每页 10 条**，提供页码切换（含省略号大页数样式）。

### 地址与 UID 复制

钱包地址、UID 在列表、详情、树节点、结算、审批详情等处以缩写展示，并提供一键复制完整值，复制成功有短暂提示。

### 页面路由（Hash）

支持浏览器 Hash 直达：`#agent`（合伙人列表）、`#partner-detail`（合伙人详情）、`#rebate-tree`（返佣关系树）、`#migrate`（迁移返佣关系）、`#approval`（合伙人审核）、`#settlement`（佣金对账）、`#logs`（操作记录）。侧栏点击与页内跳转同步更新 Hash；进入返佣树时保留 `#rebate-tree`。

## 2\.1 合伙人管理页

**访问路径**：侧边栏 → 「合伙人管理」

**页面作用**：查询一级合伙人及向下伞数据；进入详情查看团队构成；进入返佣树修改比例；新增一级合伙人。

**页头提示**：展示当前登录运营的 **权限上限（%）**。

### 2\.1\.1 查询与筛选

| 筛选项 | 说明 |
|---|---|
| 钱包 / UID / 备注 | 支持任意层级合伙人模糊查询（命中后展示对应记录） |
| 结算状态 | 全部 / 正常 / 异常（含分支异常、待修正返佣后计算等非正常状态） |

## 2\.2 返佣关系树

**入口**：合伙人列表【返佣树】、详情【返佣树 / 修改比例】、异常记录定位。

**核心原则**：无论从哪一层合伙人进入，树始终**锚定在该用户所属的一级合伙人根节点（L1 伞）**上展示完整业务线；进入深层的合伙人时，自动**定位并高亮**该节点，而非只展示以该节点为根的子树片段。

### 2\.2\.1 页面结构

- **标题**：展示焦点合伙人备注 + 所属 L1 备注 +「返佣树」。

- **暂停结算待处理区块**（若该 L1 伞存在倒挂分支）：与「迁移返佣关系」页共用同一套展示样式（见 §2.2.4）。不再使用旧的红色「异常返佣线」简表。

- **待提交修改条**：暂存未提交的比例变更，标注「权限内 · 立即生效」或「超权限 · 提交审批」。

- **操作说明**：上级链固定展示；下级默认只展示直属合伙人，点 **+** 逐层展开；多条修改后统一【提交修改】。

- **定位搜索**：在当前 L1 伞内按钱包 / UID 搜索；自动展开路径、翻页到正确的一级直属支路页、高亮节点并滚动到视区。**不会**因定位而折叠整树为单一路径。

### 2\.2\.2 树形展示规则

**一级入口节点**：L1 根固定在顶部；当焦点为 L1 时标记「当前」。

**上级链**：自焦点向上追溯至 L1，完整展示（无旁支）；链上节点均可编辑比例。

**向下展开**：

- **一级直属支路分页**：L1 的**直接下级**合伙人按支路分页展示（10 条/页），每支路可 **+ / −** 展开更深层级。

- 每个节点展示：层级、钱包、UID、备注、可编辑的返佣比例输入框。

**级差规则**：下级返佣比例**不得大于**直属上级（允许相等，级差为 0）。仅 `下级 &gt; 上级` 为倒挂异常。在输入框暂存变更时，若对含下级的节点**下调**比例，弹出提示列出直属下级当前比例，提醒确认级差影响。

### 2\.2\.3 比例修改与提交

运营在树上修改一个或多个节点比例后，变更进入「待提交修改」列表：

| 变更类型 | 新比例 vs 运营上限 | 提交后行为 |
|---|---|---|
| 权限内 | ≤ 运营上限 | 确认后立即生效 |
| 超权限 | &gt; 运营上限 | 每项生成一条「返佣比例调整（超出上限）」审批单 |

**确认提交弹窗**（点击【提交修改】后）：

| 元素 | 规则 |
|---|---|
| 变更清单 | 每条展示钱包、原比例 → 新比例、生效方式标签 |
| 混合批提示 | 若同时存在权限内与超权限项：提示仅超权限项进审批，权限内项将**自动放弃**并回滚输入框 |
| 修改原因备注 | **必填** |
| 图片附件 | 最多 **4 张**图片（PNG 等）；超上限审批时随审批单保存，供风控/老板查看 |

**确认逻辑**：

- 全部为权限内：确认后批量生效；若含下调且该节点有下级，须二次确认级差风险。

- 全部为超权限：仅提交审批，不立即改比例。

- 混合：用户确认后，超权限项提交审批；权限内项放弃并回滚。

- 超权限审批通过后，由后台执行比例更新（与一级绑定超上限审批同理）。

### 2\.2\.4 暂停结算待处理（返佣树 / 迁移返佣关系共用）

当存在返佣倒挂（下级比例 &gt; 上级）且相关分支处于暂停结算时，在**返佣关系树顶部**或**迁移预览区**展示统一的「暂停结算待处理」模块：

**顶部说明**：

- 倒挂条数：仅统计「下级 &gt; 上级」；级差为 0 不计入。

- 文案提示：比例异常期间**尚未计算应发返佣**，仅展示暂停结算的交易额与手续费。

**汇总行**：

- 暂停结算交易额合计

- 暂停结算手续费合计

**明细表列**：

| 列名 | 说明 |
|---|---|
| 上级 | 上级钱包及返佣比例 |
| 下级（倒挂） | 下级钱包及返佣比例（高于上级） |
| 暂停结算交易额 | 该倒挂分支暂停期间累计成交额 |
| 暂停结算手续费 | 该分支暂停期间累计手续费 |
| 操作 | 【展开倒挂位置】：在返佣树中展开路径并定位到该下级节点；迁移预览中在代理链路树内展开并高亮对应节点 |

**说明**：

- **不提供「待发放返佣」列**：暂停期间返佣未计算，展示应发金额不合理。

- 返佣树场景：修正下级比例后恢复结算，系统按修正后比例重算应发返佣。

- 迁移场景：副标题说明迁移并修正后，暂停数据归属新上级统计；恢复结算后按新比例计算返佣。

## 2\.3 迁移返佣关系

**访问路径**：侧栏 → 「迁移返佣关系」

**页面作用**：将普通用户或代理用户（及其伞下关系）整体迁移到新的上级合伙人之下，并设定迁移后的返佣比例；提交前须在预览中完成倒挂校验与修正。

### 2\.3\.1 录入区

| 字段 | 说明 |
|---|---|
| 待迁移用户 | 钱包或 UID；系统自动识别主体类型 |
| 迁移到上级合伙人 | 目标上级钱包或 UID |
| 设置返佣比例 (%) | 迁移主体在新上级下的比例；UI 范围 1–80（与运营上限一致） |

输入后实时进入**预览区**（主体未识别时预览为空）。

### 2\.3\.2 主体类型与迁移范围

| 类型 | 识别结果 | 迁移范围 |
|---|---|---|
| 普通用户 | 非代理账号 | 仅该用户本人；预览展示其直客列表（分页） |
| 代理用户 | 代理账号 | **整伞迁移**：该代理及其全部下级合伙人、伞下全部直客一并挂到新上级 |

预览卡片展示：类型标签、钱包、UID、系统层级 Lx、链路规模、直客数量等。

### 2\.3\.3 预览：代理用户链路树

- 以**迁移主体为根**展示代理链路树（相对标签：迁移主体 / 直接下级 / 二级下级…），并标注**系统 Lx**。

- 根节点比例 = 录入的「设置返佣比例」；根不可在树内改比例（改录入框）。

- 非根节点可在树内修改比例（用于修正倒挂或调整下级级差）。

- 迁移主体的**直接下级**支路分页（10 条/页）；更深层级 **+** 展开。

- 支持伞内**钱包 / UID 定位**（行为同返佣树：展开路径、翻页、高亮）。

- **倒挂检测**：若任一点 `子比例 > 父比例`，节点红色高亮，顶部横幅显示倒挂数量，提供「点击立即展开倒挂位置」。`子比例 = 父比例` 不视为倒挂。

### 2\.3\.4 提交前校验（必须全部通过）

| 校验项 | 规则 |
|---|---|
| 主体有效 | 待迁移用户可识别 |
| 目标上级有效 | 目标合伙人存在且可挂接 |
| 迁移比例 ≤ 目标上级比例 | 允许级差为 0；禁止迁移比例 &gt; 目标上级 |
| 迁移比例 ≤ 运营上限 | 超过须走其他特批流程（本页不允许直接提交） |
| 禁止挂在自己或自己的下级之下 | 防循环 |
| 代理用户整伞级差 | 应用所有预览中的比例覆盖后，全树满足「下级 ≤ 上级」 |
| 深层历史倒挂 | 与本次迁移比例无关的既有「下级 &gt; 上级」，须在树内先修正，倒挂计数为 0 才可提交 |

树内非根节点修改会收集为 **倒挂修正清单**（钱包、原比例 → 新比例），写入审批详情。

### 2\.3\.5 提交与审批

预览合法后，底部展示审核备注、图片附件与【提交风控审核】。

**迁移前异常伞提示**：代理用户且存在倒挂或暂停结算数据时，展示 §2.2.4「暂停结算待处理」模块（标题为「暂停结算待处理（迁移后将归属新上级统计与发放）」），含倒挂条数、暂停结算交易额/手续费汇总、明细表及每行【展开倒挂位置】操作。

确认弹窗汇总：待迁移用户、目标上级、迁移后比例、倒挂修正列表、备注、附件文件名。

提交后生成审批单「**返佣关系迁移**」，审批流：**市场运营提交 → 风控审核 → 通过即生效**（无需老板审批）。

**迁移后业绩与返佣归属**的业务规则见 §1.4「迁移后的返佣计算与业绩统计」。

### 2\.6\.5 对账单数据逻辑定义（.csv）

#### 待修正数据在对账中的处理

- 批次明细中标记为 `待修正返佣后计算` 的合伙人行：**不参与**当日「今日待发放总佣金」的实发合计；表 4（System\_Proposed\_Payout）中对应行原始佣金为待修正状态，**最终实发为 0**（或整行不进入可发放集合）。

- 表 3（分账明细流水）中，异常分支在暂停期间**不产生**可发放的获得者汇总（或产生但标记为暂停，不进入表 4 可发放汇总）。

- 影响：本页所有指标卡片、下级表、直客表中的周期数据（交易额、返佣预估、级差收入等）。

### 3\.2\.2 我的上级 / 我的返佣比例（顶部信息条）

位于指标卡片之上，左右分栏：

| 区域 | 说明 |
|---|---|
| **我的上级** | 若我为一级合伙人（无上级），展示 **一级代理**；否则展示上级钱包（可复制完整地址） |
| **我的返佣比例** | 当前账号生效的返佣比例数值（如 70%），与侧栏「最高比例」可能相同或为其下级配置上限内的当前值 |

### 3\.2\.3 核心指标卡片（4 张）

| 卡片 | 数据定义 |
|---|---|
| 团队总交易额 | 本人 + 全部下级合伙人 + 全部直客，在选定周期内的总成交额（含下级穿透） |
| 总返佣收入（本期预估） | 本期预计返佣总和；副栏拆分：**自返佣**、**直客**、**级差**。若后台已对某日佣金做**实发调减**，本卡片及周期汇总按**修正后实发**口径展示（见 §1.5） |
| 团队净入金 | 整条线净充值（充值 − 提现），含下级穿透 |
| 用户规模 | **主行**：交易用户数（周期内交易额 &gt; 0）；**次行灰色**：总用户数 |

### 3\.2\.4 团队返佣异常横幅

当本人伞下存在**团队返佣树异常**（深层链路比例倒挂，见 §1.4）时，在指标卡片与表格之间展示琥珀色横幅：

- 文案包含：异常返佣线条数、暂停结算交易额合计。

- 引导用户在下级表中查看异常明细，并与下级沟通调整比例。

**说明**：横幅描述的是**树形异常**场景；**直属下级比例高于我**的单层倒挂不在此横幅汇总，而在对应下级行的结算状态中体现。

从直属下级【查看团队】进入；支持**无限向下穿透**（下级合伙人的下级仍可【查看团队】）。

### 3\.3\.1 页头

### 3\.3\.2 我的上级 / 我的返佣比例

## 3\.4 佣金结算与发放

**访问路径**：侧栏 → 「佣金结算记录」

**页面标题**：佣金结算与发放

**页面作用**：展示佣金汇总与按日结算流水；让用户知晓每日交易额、返佣金额与结算状态。

### 3\.4\.1 汇总卡片（3 张）

| 卡片 | 说明 |
|---|---|
| 待结算佣金（今日预估） | 当前自然日预估、尚未进入最终放款的佣金 |
| 已结算总额（累计） | 历史已成功发放累计 |
| 昨日发放佣金 | 最近一个已完成发放日的实发金额及成功状态 |

### 3\.4\.2 每日结算流水

**筛选**：

- 结算日期（日期选择器，按日过滤）。

- 结算状态：全部 / 待结算 / 已结算 / 返佣异常停止结算。

**表格列**：

| 列名 | 说明 |
|---|---|
| 结算日期 | 对应自然日（日结周期见 §1.3） |
| 交易额 | 当日参与返佣计算的有效成交额 |
| 返佣金额 | 当日应展示给用户的返佣金额（**已调减实发时展示修正后实发**）；若存在违规扣减，主行下方红色小字 **违规 −$XX** |
| 结算状态 | 见下表 |

**用户侧结算状态（每日流水）**：

| 展示状态 | 业务含义 |
|---|---|
| **待结算** | 该日佣金尚未完成放款，含：批次等待对账、或后台批次**已拒绝**打回重算（用户侧统一显示待结算，不展示「已拒绝」） |
| **已结算** | 该日佣金已审核通过并完成发放 |
| **返佣异常停止结算** | 该日存在因比例异常暂停结算的交易额：**交易额 &gt; 0，返佣金额为 0**（返佣树异常或相关分支停结） |

分页：10 条/页。

### 3\.4\.3 与后台对账的对应关系（产品口径）

| 后台事实 | 用户流水展示 |
|---|---|
| 批次等待对账 | 待结算 |
| 批次已拒绝 | 待结算（不暴露拒绝） |
| 批次已放款 | 已结算 |
| 当日分支停结 / 待修正 | 返佣异常停止结算；交易额有值、返佣 0 |
| 风控调减实发 | 返佣金额按调减后实发；合伙人管理总返佣收入同步按实发累计 |
| 违规扣减 | 返佣金额下展示「违规 −$XX」 |

补发、修正比例后的历史欠发：在用户侧体现为对应日的返佣金额更新或后续日期的已结算金额，不单独使用后台「补结算」等内部状态文案（若需对用户解释，可用「已结算」+ 金额变化或帮助说明）。

## 3\.5 用户侧异常与恢复（摘要）

与 §1.4 一致，合伙人中心仅做**提示与引导**，修正操作在「调整比例」或联系下级完成：

1. **直属倒挂**：将直属下级比例调至 **≤ 我的比例** 后，该直属分支恢复结算展示。

2. **团队返佣树异常**：在异常弹窗查看各线 **停止结算交易额**，协调下级调整深层比例；全部修正后停结解除，历史停结交易额按规则重算（未放款批次内重算或走补发，用户侧最终看到修正后返佣金额）。

3. **新增下级**：自身存在倒挂或已达第 10 层时系统禁止绑定新下级合伙人。
