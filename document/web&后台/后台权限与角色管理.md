**状态**：需求设计 + 可交互原型  
**原型入口**：[权限配置后台.html#roles](https://dashuaibizzy.github.io/prototype/perp_dex/admin/权限配置后台.html#roles)  
**实现文件**：`admin-permission-registry.js`（权限注册表）、`admin-permission-store.js`（配置持久化）、`admin-permissions.js`（运行时校验）、`权限配置后台.html`（配置 UI）

---

## 1. 设计参考（行业常见做法）

成熟后台通常采用 **RBAC + 权限码**，而不是「一个角色 = 一整页」：

| 层级 | 控制什么 | 示例 |
|---|---|---|
| **菜单权限** `menu.*` | 侧栏入口是否可见 | 能否看到「体验金 · 发放审批」 |
| **动作权限** | 页内按钮 / API | `trial.recycle` 风控回收、`points.approve.cross` 积分交叉审批 |
| **数据范围**（二期） | 列表能看到哪些行 | 代理仅看自己下级 |

**同一页面、多角色协作**（审批、回收）的标准做法：

- **一个菜单入口**，不按角色复制侧栏。
- 进入后根据 **动作权限** 决定能否通过/驳回/回收。
- 列表默认「待我处理」= 用户拥有的审批动作与流程节点匹配。

本原型在顶栏提供 **「原型角色」** 下拉，选项来自「角色管理」中配置的角色；切换后立即按该角色权限矩阵刷新侧栏与敏感按钮（数据存 `localStorage`）。

## 2. 角色模型（一期）

### 2.1 内置角色

| 角色 | 说明 |
|---|---|
| **管理员** | 权限与用户管理（一般为产品总监）；默认拥有全部菜单与敏感操作 |
| **运营** | 日常发放与运营配置 |
| **市场** | 市场活动、交叉审批 |
| **测试** | 测试验证，以只读为主 |
| **产品** | 产品与规则配置（卡组、积分池等） |
| **风控** | 冻结、回收、风控审核 |
| **安全** | 安全审计、冻结日志 |
| **财务** | 佣金结算、费率 |
| **CEO** | 老板级审批视角 |

支持 **自定义角色**（可删）；内置角色不可删，可改权限矩阵。

### 2.2 用户与角色

- **一个后台用户只绑定一个角色**（不支持多角色叠加）。
- 用户登录后，权限完全由该角色的矩阵决定。
- 原型阶段用「原型角色」模拟「若以该角色登录会看到什么」。

## 3. 权限配置后台（原型功能）

### 3.1 角色管理

- 左侧角色列表（内置 / 自定义标签）。
- 右侧 **权限矩阵**：
  - 按模块折叠：菜单（📂）与动作（▸ / ⚡ 敏感）。
  - 模块级「全选 / 取消全选」。
  - 底部 **敏感操作汇总**（回收、各级交叉/风控/老板审批）。
- **保存角色权限** 后，顶栏切换「原型角色」立即生效。

### 3.2 后台用户

- 用户表：姓名、登录账号、**单一角色**、状态、最近登录。
- **新增 / 编辑 / 删除** 后台用户（需 `sys.user.manage`）。
- 管理员账号默认不可删。

### 3.3 默认进入

- 原型默认角色：**管理员**（`sessionStorage`，可见全部菜单 + 权限配置页 + 用户管理）。
- 配置数据默认种子内置 9 角色 + 示例用户；支持「恢复默认配置」。

## 4. 权限码清单（注册表）

### 4.1 系统

| 权限码 | 类型 | 说明 |
|---|---|---|
| `menu.sys.admin` | 菜单 | 权限与用户配置页 |
| `sys.role.manage` | 敏感 | 编辑角色矩阵、自定义角色 |
| `sys.user.manage` | 敏感 | 新增/编辑后台用户 |

### 4.2 体验金（示例）

| 菜单 | 敏感动作 |
|---|---|
| `menu.trial.config` … `menu.trial.logs` | `trial.issue.submit`、`trial.recycle`、`trial.approve.cross`、`trial.approve.risk`、`trial.approve.boss` |

### 4.3 积分 / 费率

- 积分：`points.approve.cross` / `points.approve.risk` / `points.approve.boss` 等。
- 费率：`fee.approve.cross` / `fee.approve.risk` / `fee.approve.boss` 等。

完整列表见 `admin-permission-registry.js`。

## 5. 与业务页面的联动

| 业务场景 | 权限码 |
|---|---|
| 侧栏显示某菜单 | 对应 `menu.*` |
| 体验金列表/详情「回收」 | `trial.recycle` |
| 体验金总览「风控回收」行 | `trial.recycle` |
| 体验金审批通过/驳回 | `trial.approve.cross` / `risk` / `boss` |
| 积分交叉审批 | `points.approve.cross` |
| 积分风控审核 | `points.approve.risk` |

## 6. 生产环境落地要点

1. **权限注册表** 前后端同源（JSON / DB），禁止前端私自扩码。
2. **登录态** 下发 `roleId` + `permissions[]`（由角色矩阵计算）。
3. **写接口** 必须校验动作权限，不仅隐藏按钮。
4. **审计**：角色矩阵变更、用户角色变更记日志。
5. **与代理「运营权限配置」**：Admin 功能权限 ≠ 代理业务数据权限，登录时合并校验。
