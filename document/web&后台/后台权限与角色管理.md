## 1. 背景与目标

### 1.1 为什么要改

原方案用「内置角色 + 权限矩阵」（运营、风控、市场…）绑定权限，存在：

- 岗位名称与真实组织不完全匹配，改一个角色影响一批人，不够灵活；
- 「菜单可见 + 动作勾选」对产品/管理员不直观；
- 审批节点与回收等敏感能力，更适合 **人员池** 管理，而非塞进角色矩阵。

### 1.2 新方案核心（三层）

```
后台人员（操作者 ID、姓名、账号、业务部门备注、系统身份）
    ├── 页面权限：每个侧栏 Tab → 无 / 读 / 写（在「编辑人员」浮层配置）
    └── 敏感操作组：把人员加入预置组（在「敏感操作组」Tab 独立维护）
```

| 层级 | 解决什么问题 |
|---|---|
| **人员** | 直接新增/编辑后台账号；用 **业务部门备注**（自由文本）代替角色标签 |
| **页面读/写** | 控制能否进入 Tab、能否 **发起** 配置/申请类操作 |
| **敏感操作组** | 控制 **审批通过/驳回、强制回收** 等高风险动作；审批待办从组内 **随机派单** |

**页面权限与敏感组分离配置**：编辑人员时 **只配页面读/写**；敏感组成员在 **敏感操作组 Tab** 通过搜索选人添加，避免人员增多后勾选列表无法展开。

### 1.3 目标与非目标

| 目标 | 说明 |
|---|---|
| 人员直配 | 无角色概念；每人独立配置页面权限；敏感组按组维护成员 |
| 读写分离 | **读** = 看全量信息，不能点「提交/保存/发放」等写操作 |
| 组池派单 | 交叉/风控/BOSS 审核待办从对应组随机指派处理人 |
| 可审计 | 人员变更、权限变更、组变更、敏感操作均留痕 |
| 账号安全 | 新增展示初始密码（仅一次）；**首次登录须绑定 Google Authenticator（GA）** |

| 非目标（本期） | 说明 |
|---|---|
| 其他模块数据行级范围 | 除合伙人管理外，体验金/积分等列表暂不做行级数据隔离 |
| 自定义敏感组 | 本期仅系统预置组，不可新建组类型 |
| 原型业务页裁剪 | 原型仍全量展示 UI；权限以本文 + 配置页为准 |
| 物理删除人员 | 仅 **停用**；停用后自动移出全部敏感组 |

## 2. 总体模型

### 2.1 后台人员

| 字段 | 必填 | 说明 |
|---|---|---|
| **操作者 ID** | 是 | 系统分配，格式 `admin-01`、`admin-02`…；创建时自动生成，**不可修改** |
| 姓名 | 是 | 展示名 |
| 登录账号 | 是 | 企业邮箱，全局唯一 |
| **业务部门备注** | 否 | **自由文本**，如「市场部」「风控一组」；仅备注，**不参与**权限计算 |
| **系统身份** | 是 | `超级管理员` 或 `普通操作人员`（见 §2.1.1） |
| 状态 | 是 | **启用** / **停用**（无物理删除） |
| GA 绑定 | — | 已绑定 / 待绑定；新建账号默认待绑定 |
| 最近登录 | — | 展示用 |

**不再有**：角色 ID、角色名称、内置角色、自定义角色。

#### 2.1.1 系统身份

| 身份 | 页面权限 | 敏感组 | 停用 |
|---|---|---|---|
| **超级管理员** | 固定拥有 **全部 Tab 读 + 写**（配置页内只读展示，不可改） | 可在敏感组 Tab 加入任意组（与运营人员相同） | **不可停用** |
| **普通操作人员** | 在编辑浮层按 Tab 逐项配置读/写 | 在敏感组 Tab 按组添加 | 可停用；停用后自动移出全部敏感组 |

新增人员时，通过 **同一弹窗** 的下拉框选择系统身份（普通操作人员 / 超级管理员）。

#### 2.1.2 新增与停用规则

| 操作 | 规则 |
|---|---|
| **新增** | 填写系统身份、姓名、登录账号、业务部门备注 → 创建成功 → 展示 **操作者 ID、登录账号、初始密码**（仅展示一次，支持一键复制） |
| **编辑** | 可改姓名、账号、业务部门备注、页面读/写（超级管理员除外）；**不可改** 操作者 ID、系统身份 |
| **停用** | 二次确认；人员状态变为停用，**自动从全部 10 个敏感组移除**；侧栏入口与敏感能力失效 |
| **启用** | 恢复为启用状态；**不自动** 恢复敏感组归属，需管理员重新添加 |
| **删除** | **不支持** |

### 2.2 页面权限（读 / 写）

每个 ForX Admin **侧栏 Tab**（含独立 HTML 页）对应一项页面权限，取值：

| 值 | 侧栏 | 页面内 |
|---|---|---|
| **无** | 不展示入口；直链拦截 | — |
| **读** | 可进入 | 可查看 **全部** 列表、详情、统计、审批进度；**不可** 点击提交/保存/发放/配置等写操作按钮 |
| **写** | 可进入 | 在「读」基础上，可发起该页定义的 **写操作**（见 §7） |

**写 ⊃ 读**：授予「写」即包含「读」。配置 UI 使用 **读 / 写** 两列勾选；勾选「写」时自动勾选「读」，取消「读」时自动取消「写」。

**特殊字段**：

| 条件 | 字段 | 规则 |
|---|---|---|
| 「合伙人管理」勾选 **读** 或 **写** | **数据权限范围** | **必填** · **全局** 或 **个人**（见下表） |
| 「合伙人管理」勾选 **写** | **一级合伙人返佣比例上限（%）** | **必填** · 整数 1–100；绑定一级合伙人时不得超过此上限 |

**合伙人管理 · 数据权限范围**（`agentDataScope`）：

| 范围 | 读 | 写 |
|---|---|---|
| **全局** | 可查看**全部**后台运营人员负责的一级合伙人及其**向下多层级**伞数据 | 可在上述全量范围内执行绑定、返佣树调整、迁移等写操作 |
| **个人** | 仅可查看**本人为配置运营（负责 BD）**的一级合伙人及其**向下多层级**伞数据 | 写操作范围同上，限于本人负责伞 |

- **超级管理员**固定为 **全局**，配置页只读展示。
- 未勾选「合伙人管理 · 读/写」时，不涉及数据范围字段。
- 业务页列表、详情、返佣树、团队穿透等**同一范围**生效；详见《[邀请合伙人无限层返佣系统](邀请合伙人无限层返佣系统.md)》§2.1.0。

### 2.3 敏感操作组（按模块拆分）

系统预置 **10 个组**；**体验金 / 积分 / 费率 各自独立审批池**，互不共用。管理员在 **敏感操作组 Tab**（非编辑人员浮层）维护成员：点击 **「+ 添加成员」** → 搜索浮窗选人 → 确认添加。

| 模块 | 组 | 用途 |
|---|---|---|
| **体验金** | 交叉审核组 | 体验金发放「待交叉审核」→ 从此组 **纯随机** 派 1 人 |
| | 风控审核组 | 体验金「待风控审核」→ 纯随机派单 |
| | BOSS 审核组 | 体验金「待老板审批」→ 纯随机派单 |
| | 强制回收组 | 仅组内可点体验金强制回收 |
| **积分** | 交叉 / 风控 / BOSS 审核组 | 手动发放、加成配置、**积分计划总开关** 等走 BOSS 节点；**积分总池配置**仅交叉 + 风控（无 BOSS） |
| **费率** | 交叉 / 风控 / BOSS 审核组 | 各管费率配置审批对应节点 |

**不在页面「写」权限内**：审批通过/驳回、强制回收 — 必须 **单独入组**。

**组成员约束**：

- 仅 **启用** 状态人员可被加入；
- 一人可入 **多个组**（例如同时在体验金风控组 + 体验金回收组 + 积分风控组）；
- 停用后 **自动移出全部组**。

### 2.4 审批派单规则

1. 单据进入某模块某审批节点时，从 **该模块该节点对应组** 的在岗（启用）成员中 **纯随机** 抽 1 人作为处理人（「待我审批」）。
2. 体验金交叉审核 **不会** 从积分/费率交叉组派人。
3. 仅被派单的处理人可点通过/驳回；同组其他人可在「全部审批」只读查看（须该 Tab 为读或写）。
4. 处理人停用或移出组后：未完成单 **重新纯随机** 派单。
5. **不可自审自批**：派单时排除提交人本人。

### 2.4.1 驳回重提（#257 · 全模块统一）

体验金、积分、费率、合伙人等 **所有** 模块审批均支持：申请单 **已驳回** 后，**原申请人** 可在详情页基于 **原 payload** 重新提交，审批流从头开始。

| 项 | 说明 |
|---|---|
| 保留内容 | 名单、配置变更、附件快照、迁移方案等 **申请原数据不可改** |
| 可修改项 | **申请备注** |
| 可见条件 | 状态 = 已驳回，且当前查看者为该单 `applicant` |
| 跨模块 | 各模块独立 seed 与敏感组；行为一致，文案按审批类型略有差异 |

详见各模块文档「驳回重提说明」及《[修改记录 · 20260828](../修改记录/20260828-points-uid-resubmit.md)》。

### 2.5 谁可以改权限

「**权限与用户**」Tab 的 **写** 权限 = 可维护人员、页面权限、敏感操作组成员（通常仅 1～2 名系统负责人 + 超级管理员）。该 Tab 由种子数据中的超级管理员持有。

## 3.1 Admin 通用列表交互（分页与 UID/地址复制）

除 **代理中心**（见《邀请合伙人无限层返佣系统》独立文档）外，ForX Admin 各业务列表统一遵循本节规范。

### 列表分页

| 规则 | 说明 |
|---|---|
| 每页条数 | **10 条** |
| 控件样式 | `< 1 2 3 ... N >`（上一页、页码按钮、省略号、下一页） |
| 空列表 / 不足一页 | **仍展示分页器**（默认第 1 页；无数据或仅一页时上一页/下一页置灰），便于运营感知列表支持分页 |
| 筛选 / 查询 / 重置 | 列表重置为 **第 1 页** 后重新分页 |
| 详情子表 | 进入用户详情等子页时，子表分页独立计数；返回列表不联动 |
| 审批名单 | 体验金 / 积分 / 费率审批详情中的发放名单、配置名单同样每页 10 条 |

**各模块分页位置**（代理中心不在此表，单独维护）：

| 模块 | 分页位置 |
|---|---|
| 系统 · 权限与用户 | 后台人员列表 |
| 体验金 | 卡组配置列表、用户查询列表、操作记录；用户详情内卡券列表、使用流水 |
| 风控冻结 | 用户冻结设置列表、冻结操作记录 |
| 排行榜 | 影子账户池列表 |
| 费率 | 用户费率设置列表、费率操作记录；各模块审批列表与详情内名单 |
| 积分 | 每周发放记录、发放明细用户表、用户积分列表、积分流水、操作记录 |

### UID / 钱包地址展示与复制

| 规则 | 说明 |
|---|---|
| 展示 | 列表中 **UID 为主键展示**；钱包/邮箱为次要行，默认 **缩写展示**（钱包如 `0x7a3f...9c2e`；长 UID 按 `前4…后4`） |
| 复制 | 缩写右侧 **复制图标**；点击复制 **完整原始值**（非缩写） |
| 反馈 | 复制成功 Toast「已复制」 |
| 适用范围 | 体验金、风控冻结、费率、积分、排行榜等后台列表；权限配置页人员 ID 为明文展示（非用户 UID） |

## 5. 敏感操作组明细（10 个，按模块独立）

| 组 ID（实现用） | 展示名 | 成员能做什么 |

## 6. 权限配置后台 · 功能需求

**入口**：ForX Admin → 系统 → **权限与用户**  
**原型文件**：`perp_dex/admin/权限配置后台.html`

### 6.2 Tab：后台人员

#### 6.2.1 人员列表

| 列 | 说明 |

列表底部统一分页器（见 §3.1）：每页 10 条，`< 1 2 3 ... N >`；不足一页仍展示。

#### 6.2.2 新增人员（统一弹窗）

| 元素 | 说明 |
|---|---|
| 入口 | 列表右上角 **「+ 新增后台人员」**（普通操作人员与超级管理员 **共用一个按钮**） |
| 系统身份 | 下拉：**普通操作人员** / **超级管理员** |
| 表单 | 姓名、登录账号（邮箱）、业务部门备注 |
| 创建成功 | 关闭创建弹窗 → 打开 **初始凭证弹窗**：操作者 ID、登录账号、初始密码、系统身份；**一键复制全部信息** |
| 安全 | 初始密码 **仅展示一次**；账号 **首次登录须绑定 GA** 后方可使用后台 |

#### 6.2.3 编辑人员（右侧浮层 Drawer）

点击列表 **「编辑」** 从右侧滑出浮层（非居中弹窗）。

**基本信息区（表格式）**

| 字段 | 可编辑 |
|---|---|
| 姓名 | 是 |
| 操作者 ID | 否（只读展示） |
| 登录账号 | 是 |
| 业务部门备注 | 是 |
| 账号状态 | 否（只读标签） |
| 系统身份 | 否（只读展示） |

**超级管理员**：顶部提示条「固定拥有全部页面读 + 写」；下方页面权限表全部勾选且 **禁用**。

**页面权限区**

- 按 **模块** 分组（体验金、积分、费率…）；
- 每个 Tab 一行：**页面名 | 读 ☐ | 写 ☐**；
- 勾选「写」自动勾选「读」；取消「读」自动取消「写」；
- **不包含敏感操作组**（敏感组在独立 Tab 维护）。

**一级代理返佣上限**

- 当「合伙人管理」勾选 **写** 时，展示 **一级合伙人返佣比例上限（%）** 输入框（整数 1–100，**必填**）。
- 保存时若已勾选写权限但未填上限，**阻断保存**并提示。

**合伙人管理 · 数据权限范围**

- 当「合伙人管理」勾选 **读** 或 **写** 时，展示 **数据权限范围** 下拉：**全局** / **个人**（**必填**）。
- 说明文案：全局 = 全部运营负责的多层级合伙人数据；个人 = 仅本人负责的多层级合伙人数据。
- 保存时若已勾选读/写但未选范围，**阻断保存**并提示。
- **超级管理员**固定全局，不展示下拉。

**底栏**：取消 / **保存**（仅写入基本信息与页面读/写）。

### 6.3 Tab：敏感操作组

按 **10 个预置组** 展示可折叠卡片：

| 区域 | 说明 |
|---|---|
| 卡片标题 | 组名 + 说明文案 |
| 标题右侧 | **「+ 添加成员」** 按钮（无需先展开卡片即可点击）+ 当前人数 |
| 展开内容 | 成员 **Chip 标签**（姓名 + 操作者 ID）；点击 **×** 移出该组 |

#### 6.3.1 添加成员浮窗

点击 **「+ 添加成员」** 打开居中浮窗：

| 元素 | 说明 |
|---|---|
| 搜索框 | 按 **姓名 / 操作者 ID / 邮箱 / 业务部门备注** 模糊筛选 |
| 候选列表 | 展示启用且 **尚未在本组** 的人员；点击选中高亮 |
| 确认 | **确认添加** 将选中人员加入当前组；**取消** 关闭 |

**设计原因**：人员规模增大时，不宜在编辑人员或组内使用勾选网格；搜索选人可扩展。

### 6.4 恢复默认配置

二次确认后清空本地配置并恢复内置模拟数据，刷新当前 Tab 列表。（具体人员与组归属以原型代码为准，不在 PRD 逐条维护。）

## 7. 与业务页面联动（正式上线）

### 7.1 侧栏

- Tab 页面权限 = **无** → 侧栏隐藏；
- **读** 或 **写** → 展示入口。

### 7.2 按钮级

| 场景 | 条件 |
|---|---|
| 提交类（发放、费率申请、积分配置提交…） | 对应 Tab = **写** |
| 审批通过/驳回 | 在该 **模块** 对应 **敏感组** 内，且为 **被派单处理人** |
| 体验金回收 | 在 **体验金 · 强制回收组** |
| 只读 Tab 内所有按钮 | 仅 **读** 时全部隐藏或禁用 |

### 7.3 代理返佣上限

运营人员在「合伙人管理」绑定时，输入比例 **≤** 该账号配置的返佣比例上限；超限前端校验 + 服务端拒绝。人员编辑页勾选「合伙人管理 · 写」时，**必须**先填写上限方可保存。

### 7.4 登录与 GA

| 项 | 要求 |
|---|---|
| 首次登录 | 须完成 **GA 绑定** 后进入后台 |
| 登录下发 | 操作者 ID、系统身份、页面权限 Map、所属敏感组 ID 列表、agentMaxRebate（若有）、**agentDataScope**（合伙人管理读/写时） |
| 变更生效 | 重新登录或 token 刷新后生效 |

### 7.5 审计（正式上线）

人员新增/编辑/启用/停用、页面权限变更、敏感组成员变更、审批派单与审批/回收执行，均须留痕（操作者、目标、变更内容或单据结果）。
