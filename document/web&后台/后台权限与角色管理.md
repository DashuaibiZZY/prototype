## 1. 背景与目标

### 1.1 为什么要改

原方案用「内置角色 + 权限矩阵」（运营、风控、市场…）绑定权限，存在：

- 岗位名称与真实组织不完全匹配，改一个角色影响一批人，不够灵活；
- 「菜单可见 + 动作勾选」对产品/管理员不直观；
- 审批节点与回收等敏感能力，更适合 **人员池** 管理，而非塞进角色矩阵。

### 1.2 新方案核心（三层）

```
后台人员（姓名、账号、业务部门备注）
    ├── 页面权限：每个侧栏 Tab → 无 / 读 / 写
    └── 敏感操作组：把人员加入预置组（交叉审核、风控审核、BOSS 审核、强制回收…）
```

| 层级 | 解决什么问题 |
|---|---|
| **人员** | 直接增删后台账号；用 **业务部门备注**（自由文本）代替角色标签 |
| **页面读/写** | 控制能否进入 Tab、能否 **发起** 配置/申请类操作 |
| **敏感操作组** | 控制 **审批通过/驳回、强制回收** 等高风险动作；审批待办从组内 **随机派单** |

### 1.3 目标与非目标

| 目标 | 说明 |
|---|---|
| 人员直配 | 无角色概念；每人独立配置页面权限与组归属 |
| 读写分离 | **读** = 看全量信息，不能点「提交/保存/发放」等写操作 |
| 组池派单 | 交叉/风控/BOSS 审核待办从对应组随机指派处理人 |
| 可审计 | 人员变更、权限变更、组变更、敏感操作均留痕 |

| 非目标（本期） | 说明 |
|---|---|
| 数据行级范围 | 如按代理树过滤列表（二期） |
| 自定义敏感组 | 本期仅系统预置组，不可新建组类型 |
| 原型业务页裁剪 | 原型仍全量展示 UI；权限以本文 + 配置页为准 |

## 2. 总体模型

### 2.1 后台人员

| 字段 | 必填 | 说明 |
|---|---|---|
| 姓名 | 是 | 展示名 |
| 登录账号 | 是 | 企业邮箱 |
| **业务部门备注** | 否 | **自由文本**，如「市场部」「风控一组」「外包-审核」；仅备注，**不参与**权限计算 |
| 状态 | 是 | 启用 / 停用 |
| 最近登录 | — | 展示用 |

**不再有**：角色 ID、角色名称、内置角色、自定义角色。

### 2.2 页面权限（读 / 写）

每个 ForX Admin **侧栏 Tab**（含独立 HTML 页）对应一项页面权限，取值：

| 值 | 侧栏 | 页面内 |
|---|---|---|
| **无** | 不展示入口；直链拦截 | — |
| **读** | 可进入 | 可查看 **全部** 列表、详情、统计、审批进度；**不可** 点击提交/保存/发放/配置等写操作按钮 |
| **写** | 可进入 | 在「读」基础上，可发起该页定义的 **写操作**（见 §7） |

**写 ⊃ 读**：授予「写」即包含「读」，无需重复配置。

**特殊字段**：当「一级代理管理」为 **写** 时，须同时配置该人员的 **一级代理返佣比例上限（%）**（整数，如 70）；绑定一级代理时不得超过此上限。

### 2.3 敏感操作组

系统预置若干 **组**；管理员将人员 **加入/移出** 组，组本身不可改名、不可新增类型（本期）。

| 组名称 | 用途 | 典型业务 |
|---|---|---|
| **市场运营交叉审核组** | 审批池 | 体验金/积分/费率 交叉审核节点：待办 **随机** 派给组内一人 |
| **风控审核组** | 审批池 | 上述三模块的风控审核节点：随机派单 |
| **BOSS 审核组** | 审批池 | 上述三模块的老板审批节点：随机派单（可与 Lark 联动） |
| **体验金强制回收组** | 操作池 | 仅组内人员可见并可点击「回收」类按钮 |

**不在页面「写」权限内**：审批通过/驳回、强制回收 — 即使某页是「写」，也不能自动获得审批/回收能力，必须 **单独入组**。

### 2.4 审批派单规则

1. 单据进入某审批节点（如「待市场运营交叉审核」）时，系统从 **对应组** 的在岗成员中 **随机抽取 1 人** 作为当前处理人（「待我审批」）。
2. 同组其他人可在「全部审批」视图中 **只读** 查看（若该 Tab 为「读」或「写」）。
3. 仅 **被派单的处理人** 可点通过/驳回（须在该组内）。
4. 处理人停用或移出组后：未完成单 **重新随机** 派给组内其他成员。
5. **不可自审自批**：提交人不得与当前节点处理人为同一人（若在同组，派单时排除提交人）。

### 2.5 谁可以改权限

「**权限与用户**」Tab 的 **写** 权限 = 可维护人员、页面权限、敏感操作组（通常仅 1～2 名系统负责人）。该 Tab **不出现在** 其他人的页面权限配置矩阵中由他人勾选——由种子数据直接赋予首位管理员。

## 5. 敏感操作组明细

| 组 | 成员能做什么 | 不能做什么 |
|---|---|---|
| 市场运营交叉审核组 | 对处于「待交叉审核」的单据 **通过/驳回**（体验金发放、积分相关审批、费率配置） | 不能代替提交申请；不能执行风控/BOSS 节点 |
| 风控审核组 | 对「待风控审核」单据通过/驳回 | 不能交叉/BOSS 审批；不能强制回收（除非另入回收组） |
| BOSS 审核组 | 对「待老板审批」单据通过/驳回（Web 或 Lark） | 不能交叉/风控审批 |
| 体验金强制回收组 | 用户列表/详情/总览中 **回收** 按钮可用并执行 | 不能提交发放；不能审批 |

**一人可入多组**（例如既在风控审核组，也在体验金强制回收组）。

## 6. 权限配置后台 · 功能需求

**入口**：ForX Admin → 系统 → **权限与用户**

### 6.1 顶栏 Tab

| Tab | Hash | 功能 |
|---|---|---|
| **后台人员** | `#staff` | 人员 CRUD、业务部门备注 |
| **页面权限** | `#pages` | 按人选 Tab，配置 无/读/写；一级代理写权限配返佣上限 |
| **敏感操作组** | `#groups` | 四个预置组的成员维护 |

右上角：**恢复默认配置**（重置为种子人员与权限）。

### 6.2 Tab：后台人员

**列表列**：姓名、登录账号、业务部门备注、状态、最近登录、操作（编辑/删除）

**新增/编辑弹窗**：

| 字段 | 必填 |
|---|---|
| 姓名 | 是 |
| 登录账号（邮箱） | 是 |
| 业务部门备注 | 否，自由文本 |
| 状态 | 启用/停用 |

**规则**：种子超级管理员不可删除；删除人员时同步从各敏感组移除。

### 6.3 Tab：页面权限

**交互**：

1. 左侧或顶部 **选择一名人员**；
2. 右侧按模块分组展示 §3 全部 Tab；
3. 每项三个单选：**无 / 读 / 写**；
4. 当「一级代理管理」= 写 时，展示 **返佣比例上限（%）** 数字输入框，必填；
5. **保存** 后生效（原型 localStorage；正式环境服务端）。

**批量能力（P2）**：复制另一人的页面权限、按模块全选读/写。

### 6.4 Tab：敏感操作组

**布局**：四个组卡片或左侧组列表 + 右侧成员。

每组展示：

- 组名称与说明（§5）；
- 当前成员列表（姓名 + 业务部门备注 + 移除）；
- **添加成员**：从已启用人员中搜索选择（可多选）。

**规则**：

- 组内至少 0 人；若为 0，对应审批节点无处理人，单据滞留并告警；
- 审批派单逻辑见 §2.4。

### 6.5 恢复默认配置

二次确认后恢复种子数据（见 §8），清除所有自定义变更。

## 7. 与业务页面联动（正式上线）

### 7.1 侧栏

- Tab 页面权限 = **无** → 侧栏隐藏；
- **读** 或 **写** → 展示入口。

### 7.2 按钮级

| 场景 | 条件 |
|---|---|
| 提交类（发放、费率申请、积分配置提交…） | 对应 Tab = **写** |
| 审批通过/驳回 | 当前用户在对应 **敏感组**，且为 **被派单处理人** |
| 体验金回收 | 当前用户在 **体验金强制回收组** |
| 只读 Tab 内所有按钮 | 仅 **读** 时全部隐藏或禁用 |

### 7.3 代理返佣上限

运营人员在「一级代理管理」绑定时，输入比例 **≤** 该账号配置的返佣比例上限；超限前端校验 + 服务端拒绝。
