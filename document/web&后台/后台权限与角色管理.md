# 后台权限与角色管理

**状态**：需求设计（原型已用 `admin-permissions.js` 演示角色切换与动作级权限）  
**关联原型**：`perp_dex/admin/admin-permissions.js`、`perp_dex/admin/admin-sidebar.js`

---

## 1. 背景与目标

ForX Admin 包含代理中心、体验金、风控冻结、排行榜、费率、积分等多个模块。各模块菜单不同，且同一页面内常出现「多人可进页、但可操作不同」的场景（审批、风控回收等）。

**目标**：

1. 统一权限模型，避免「每页一套 Tab 模拟角色」长期散落。
2. 支持 **菜单可见性** 与 **页面内动作** 两级控制。
3. 支持 **多角色共享同一菜单/页面**，通过 **权限码** 而非重复菜单项区分能力。
4. 后端 API 与前端 UI 使用同一套权限码，防止越权。

---

## 2. 核心模型：RBAC + 权限码（推荐）

不要只用「角色」绑菜单。采用三层结构：

```
用户 (User) ──多对多──▶ 角色 (Role) ──多对多──▶ 权限 (Permission)
```

- **用户**：登录账号，可绑定多个角色（权限取并集）。
- **角色**：业务岗位抽象，如「体验金管理员」「风控」「市场运营交叉」。
- **权限**：最小能力单元，字符串编码，分为两类：
  - **菜单权限** `menu.<模块>.<页面>` — 控制侧栏是否展示入口。
  - **动作权限** `<模块>.<动作>` — 控制按钮、接口、字段是否可用。

示例：

| 权限码 | 类型 | 说明 |
|---|---|---|
| `menu.trial.users` | 菜单 | 可见「数据查询&回收」入口 |
| `trial.recycle` | 动作 | 可执行风控强制回收 |
| `trial.approval.view` | 动作 | 可进入体验金发放审批页并查看 |
| `trial.approve.risk` | 动作 | 可在审批流中执行风控审核通过/驳回 |

**多角色访问同一页**：给不同角色分配 **同一菜单权限** + **不同的动作权限** 即可，无需复制页面或侧栏项。

---

## 3. 与「仅角色控制」的对比

| 方式 | 优点 | 缺点 |
|---|---|---|
| 仅角色 | 实现简单 | 角色爆炸；「进页」与「操作」难拆分；一人多岗难表达 |
| **角色 + 权限码（推荐）** | 菜单与动作解耦；多角色并集；审批/回收可细控 | 需维护权限矩阵与配置后台 |
| 纯 ABAC（属性） | 数据范围灵活 | 复杂度高，适合二期数据域（如代理只看自己下级） |

结论：**一期 RBAC + 权限码**；二期在权限校验上叠加 **数据范围**（如 `data_scope.agent_tree`）。

---

## 4. 菜单 vs 动作：落地规则

### 4.1 侧栏（菜单）

- 每个侧栏项绑定一个 `menu.*` 权限。
- 用户无任何一项子菜单权限时，整个模块分组隐藏。
- **不因角色不同而重复侧栏项**（例如审批页只有一个「发放审批」入口）。

### 4.2 页面内

| 场景 | 做法 |
|---|---|
| 体验金「数据查询&回收」 | 菜单 `menu.trial.users`；回收按钮、风控回收指标依赖 `trial.recycle` |
| 体验金/积分/费率审批 | 菜单 `menu.*.approval` + `*.approval.view`；通过/驳回依赖 `*.approve.cross/risk/boss` |
| 只读审计 | 仅 `menu.trial.logs`，无发放、无回收 |
| 老板 Lark 审批 | 后台可只读 `approval.view`；实际审批在 Lark，权限可不在 Web 开放 `approve.boss` |

### 4.3 后端

- 每个写操作 API 声明所需权限码；网关或业务层校验。
- 前端隐藏按钮 **不能** 代替后端校验。

## 5. 审批类页面的特殊处理

审批是典型「多角色同页」场景，建议：

1. **一个审批菜单、一个列表页** — 所有有 `*.approval.view` 的角色可见。
2. **列表过滤** — 默认「待我处理」：根据用户拥有的 `*.approve.*` 权限匹配当前节点。
3. **详情页按钮** — 仅当 `canApprove(app, userPermissions)` 为真时展示通过/驳回。
4. **原型角色 Tab** — 仅演示用；生产改为真实登录权限，可移除 Tab 或保留为「预览模式」。

与体验金回收同理：**页面对运营可见，回收动作仅 `trial.recycle`**。

## 7. 权限配置后台（独立需求）

建议在 Admin 增加 **系统设置 → 角色与权限**（仅超级管理员），包含：

### 7.1 角色管理

- 角色列表：名称、描述、是否系统内置（不可删）。
- 新建自定义角色（二期）。

### 7.2 权限矩阵

- 树形展示：模块 → 菜单 → 动作。
- 勾选保存角色拥有的权限码。
- 支持「复制角色权限」。

### 7.3 用户绑定

- 用户列表：账号、姓名、已绑角色（多选）。
- 支持搜索、批量导入（企业 SSO 对接后同步）。

### 7.4 审计

- 权限变更日志：谁、何时、改了哪个角色/用户。

**与代理中心「运营权限配置」关系**：代理侧是 **业务数据权限**（返佣比例、下级可见范围）；本需求是 **Admin 系统功能权限**，两套体系并存，登录上下文合并校验。

## 8. 技术实现要点

### 8.1 权限码注册表

维护一份 `permissions.json`（或 DB 表），作为前后端唯一来源：

```json
{
  "menu.trial.users": { "label": "体验金 · 数据查询", "group": "trial" },
  "trial.recycle": { "label": "体验金 · 风控回收", "group": "trial", "type": "action" }
}
```

### 8.2 登录态

```json
{
  "userId": "u_001",
  "roles": ["trial_admin"],
  "permissions": ["menu.trial.config", "menu.trial.issue", ...]
}
```

权限列表由服务端根据角色计算后下发，前端缓存；变更后强制刷新或短 TTL。

### 8.3 前端

- `hasPerm('trial.recycle')` 控制按钮与敏感指标。
- 侧栏根据 `menu.*` 过滤。
- 路由守卫：无菜单权限跳转 403 页。

### 8.4 原型演示

- 顶栏 **原型角色** 下拉切换 `sessionStorage` 中的演示角色。
- 切换后刷新侧栏与当前页动作区（监听 `admin-role-change`）。
