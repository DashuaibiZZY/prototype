# 后台权限与角色管理

**状态**：需求设计 + 可交互原型（2026-07 迭代）  
**原型入口**：[权限配置后台.html#roles](https://dashuaibizzy.github.io/prototype/perp_dex/admin/权限配置后台.html#roles)  
**关联实现**：`perp_dex/admin/admin-permission-registry.js`、`admin-permission-store.js`、`admin-permissions.js`、`权限配置后台.html`、`admin-sidebar.js`

---

## 1. 概述

ForX Admin 包含代理中心、体验金、风控冻结、排行榜、费率、积分及 **系统（权限与用户）** 等模块。各模块菜单不同；同一页面内常出现「多人可进入、但可操作不同」的场景（审批节点、风控回收等）。

本需求定义：

1. **角色**与**权限码**（菜单 + 敏感动作）的配置方式；
2. **权限配置后台**原型交互；
3. 与各业务子页面（体验金数据查询&回收、积分发放总览等）的权限对应关系。

### 1.1 原型 vs 生产

| 维度 | 原型行为 | 生产环境目标 |
|---|---|---|
| 业务子页面 UI | **全量展示**（所有菜单、按钮均可见可点） | 按登录用户角色权限显隐 |
| 权限差异说明 | 本文档 + **权限配置后台** 矩阵 | 登录态下发 `permissions[]`，前后端一致校验 |
| 角色切换预览 | **不提供**顶栏「原型角色」切换 | 真实账号登录 |
| 配置持久化 | 浏览器 `localStorage`（`forx_admin_permission_store`） | 服务端 DB + 审计日志 |

## 2. 设计模型：RBAC + 权限码

```
后台用户（1 个角色）──▶ 角色 ──▶ 权限码列表（菜单 menu.* + 动作）
```

| 类型 | 编码示例 | 控制范围 |
|---|---|---|
| **菜单权限** | `menu.trial.users` | 侧栏是否展示该入口 |
| **动作权限** | `trial.recycle` | 页内按钮、API 写操作 |
| **数据范围**（二期） | `data_scope.agent_tree` | 列表可见数据行 |

**多角色协作同一页**（审批、回收）：**一个侧栏入口** + 不同 **动作权限**（交叉审批 / 风控审核 / 老板审批），不按角色复制菜单项。

## 4. 权限配置后台（原型详解）

**文件**：`perp_dex/admin/权限配置后台.html`  
**侧栏**：系统 → **权限与用户**

### 4.1 页面结构

顶栏 Tab：

| Tab | Hash | 标题 |
|---|---|---|
| 角色管理 | `#roles` | 角色与权限 |
| 后台用户 | `#users` | 后台用户 |

右上角：**恢复默认配置**（重置种子角色与用户，清除自定义角色）。

### 4.2 角色管理 Tab

**布局**：左侧角色列表（宽约 280px）+ 右侧权限矩阵。

#### 左侧 · 角色列表

| 元素 | 说明 |
|---|---|
| 角色卡片 | 展示角色名、内置/自定义标签、说明文案、已配置权限项数（「全部」或 N 项） |
| 选中态 | 蓝色边框高亮 |
| **+ 自定义** | 打开「新增自定义角色」弹窗 |
| 底部提示 | 内置角色不可删除；选中后右侧配置权限范围 |

**内置角色（9 个）**：管理员、运营、市场、测试、产品、风控、安全、财务、CEO。  
**自定义角色**：可删除；删除后绑定该角色的用户改为「测试」角色。

#### 右侧 · 权限矩阵

选中角色后展示：

| 区域 | 说明 |
|---|---|
| 标题区 | `角色名 · 权限范围`、说明、已选 N / 全量 或「全部权限」标签 |
| 模块折叠块 | 按业务模块（代理中心、体验金、风控冻结…）分组 |
| 模块头 | 模块名 + **全选本模块** / **取消全选** |
| 菜单项 | 文案 +「菜单可见」副标题；可勾选 |
| 动作项 | 普通动作或 **敏感操作**（琥珀色底）；可勾选 |
| 敏感操作汇总 | 底部琥珀色区块，展示所有敏感动作标签及当前角色是否拥有 |
| 底栏 | **重置**（放弃未保存编辑）、**保存角色权限**、自定义角色 **删除角色** |

**管理员角色**：权限数据为 `*`（全部）；矩阵中全部勾选，标签显示「全部权限」；保存时若全选仍写入 `*`。

**不在矩阵中的项**：见 §5.1 管理员专属权限（系统设置相关三项不出现在矩阵 UI）。

#### 新增自定义角色弹窗

| 字段 | 必填 | 说明 |
|---|---|---|
| 角色名称 | 是 | 如「外包审核」 |
| 说明 | 否 | 角色用途 |
| 创建 | — | 创建后权限为空，需在矩阵中勾选并保存 |

## 9. 生产环境落地要点

1. **权限注册表**前后端同源（建议 `permissions.json` 或 DB 表），与 `admin-permission-registry.js` 对齐。
2. 登录响应包含 `roleId`、`roleName`、`permissions[]`（由角色矩阵展开，管理员含 §5.1）。
3. **写接口**声明 `requiredPermission`，网关或业务层强制校验。
4. **审计**：角色矩阵变更、用户角色变更、敏感操作执行均记日志。
5. **单用户单角色**：不支持多角色并集；如需多岗，由产品定义「复合角色」而非多绑。
6. **与代理运营权限配置**：Admin RBAC ≠ 代理返佣上限等业务权限。
