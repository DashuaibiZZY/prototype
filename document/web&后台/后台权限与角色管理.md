## 1. 背景与目标

### 1.1 为什么要改

原方案用「内置角色 + 权限矩阵」（运营、风控、市场…）绑定权限，存在：

- 岗位名称与真实组织不完全匹配，改一个角色影响一批人，不够灵活；
- 「菜单可见 + 动作勾选」对产品/管理员不直观；
- 审批节点与回收等敏感能力，更适合 **人员池** 管理，而非塞进角色矩阵。

### 1.2 新方案核心（三层）

```
后台人员（姓名、账号、业务部门备注）
    ├── 页面权限：每个侧栏 Tab → 无 / 读 / 写
    └── 敏感操作组：把人员加入预置组（交叉审核、风控审核、BOSS 审核、强制回收…）
```

| 层级 | 解决什么问题 |
|---|---|
| **人员** | 直接增删后台账号；用 **业务部门备注**（自由文本）代替角色标签 |
| **页面读/写** | 控制能否进入 Tab、能否 **发起** 配置/申请类操作 |
| **敏感操作组** | 控制 **审批通过/驳回、强制回收** 等高风险动作；审批待办从组内 **随机派单** |

### 1.3 目标与非目标

| 目标 | 说明 |
|---|---|
| 人员直配 | 无角色概念；每人独立配置页面权限与组归属 |
| 读写分离 | **读** = 看全量信息，不能点「提交/保存/发放」等写操作 |
| 组池派单 | 交叉/风控/BOSS 审核待办从对应组随机指派处理人 |
| 可审计 | 人员变更、权限变更、组变更、敏感操作均留痕 |

| 非目标（本期） | 说明 |
|---|---|
| 数据行级范围 | 如按代理树过滤列表（二期） |
| 自定义敏感组 | 本期仅系统预置组，不可新建组类型 |
| 原型业务页裁剪 | 原型仍全量展示 UI；权限以本文 + 配置页为准 |

## 2. 总体模型

### 2.1 后台人员

| 字段 | 必填 | 说明 |
|---|---|---|
| 姓名 | 是 | 展示名 |
| 登录账号 | 是 | 企业邮箱 |
| **业务部门备注** | 否 | **自由文本**，如「市场部」「风控一组」「外包-审核」；仅备注，**不参与**权限计算 |
| 状态 | 是 | 启用 / 停用 |
| 最近登录 | — | 展示用 |

**不再有**：角色 ID、角色名称、内置角色、自定义角色。

### 2.2 页面权限（读 / 写）

每个 ForX Admin **侧栏 Tab**（含独立 HTML 页）对应一项页面权限，取值：

| 值 | 侧栏 | 页面内 |
|---|---|---|
| **无** | 不展示入口；直链拦截 | — |
| **读** | 可进入 | 可查看 **全部** 列表、详情、统计、审批进度；**不可** 点击提交/保存/发放/配置等写操作按钮 |
| **写** | 可进入 | 在「读」基础上，可发起该页定义的 **写操作**（见 §7） |

**写 ⊃ 读**：授予「写」即包含「读」，无需重复配置。

**特殊字段**：当「一级代理管理」为 **写** 时，须同时配置该人员的 **一级代理返佣比例上限（%）**（整数，如 70）；绑定一级代理时不得超过此上限。

### 2.3 敏感操作组（按模块拆分）

系统预置 **10 个组**；**体验金 / 积分 / 费率 各自独立审批池**，互不共用。管理员在 **编辑人员** 时勾选组归属。

| 模块 | 组 | 用途 |
|---|---|---|
| **体验金** | 交叉审核组 | 体验金发放「待交叉审核」→ 从此组 **纯随机** 派 1 人 |
| | 风控审核组 | 体验金「待风控审核」→ 纯随机派单 |
| | BOSS 审核组 | 体验金「待老板审批」→ 纯随机派单 |
| | 强制回收组 | 仅组内可点体验金回收 |
| **积分** | 交叉 / 风控 / BOSS 审核组 | 各管积分模块对应审批节点（总池配置无 BOSS 节点） |
| **费率** | 交叉 / 风控 / BOSS 审核组 | 各管费率配置审批对应节点 |

**不在页面「写」权限内**：审批通过/驳回、强制回收 — 必须 **单独入组**。

### 2.4 审批派单规则

1. 单据进入某模块某审批节点时，从 **该模块该节点对应组** 的在岗成员中 **纯随机** 抽 1 人作为处理人（「待我审批」）。
2. 体验金交叉审核 **不会** 从积分/费率交叉组派人。
3. 仅被派单的处理人可点通过/驳回；同组其他人可在「全部审批」只读查看（须该 Tab 为读或写）。
4. 处理人停用或移出组后：未完成单 **重新纯随机** 派单。
5. **不可自审自批**：派单时排除提交人本人。

### 2.5 谁可以改权限

「**权限与用户**」Tab 的 **写** 权限 = 可维护人员、页面权限、敏感操作组（通常仅 1～2 名系统负责人）。该 Tab **不出现在** 其他人的页面权限配置矩阵中由他人勾选——由种子数据直接赋予首位管理员。

## 6. 权限配置后台 · 功能需求

**入口**：ForX Admin → 系统 → **权限与用户**

### 6.1 顶栏 Tab

| Tab | Hash | 功能 |
|---|---|---|
| **后台人员** | `#staff` | 人员列表；**编辑** 打开侧栏式弹窗，一次配齐页面读/写 + 敏感组 |
| **敏感操作组** | `#groups` | 十组只读总览（成员名单）；编辑归属在人员弹窗内勾选 |

右上角：**恢复默认配置**。

### 6.2 编辑人员弹窗（核心交互）

**布局**：大屏弹窗 = **左侧深色页面导航**（同 ForX Admin 侧栏结构）+ **右侧配置区**。

| 区域 | 内容 |
|---|---|
| 左侧导航 | 按模块列出全部 Tab，点击 **锚点跳转** 到右侧对应行 |
| 基本信息 | 姓名、账号、业务部门备注、状态 |
| 页面权限 | **一次性列出全部 Tab**，每行 **无 / 读 / 写** 三按钮；写 ⊃ 读 |
| 一级代理上限 | 「一级代理管理」= 写 时展示返佣比例上限（%） |
| 敏感操作组 | 按模块分组 **勾选** 10 个预置组 |
| 底栏 | 取消 / **保存**（同时写入页面权限与组归属） |

**列表摘要列**：展示该人员「页面写 N 项 · 敏感组 M 个」，便于扫一眼。

### 6.3 Tab：敏感操作组（只读总览）

按模块卡片展示 10 组：组名、说明、当前成员姓名标签。修改成员请回到 **编辑人员** 弹窗。

### 6.4 恢复默认配置

二次确认后恢复 §8 种子数据。

## 7. 与业务页面联动（正式上线）

### 7.1 侧栏

- Tab 页面权限 = **无** → 侧栏隐藏；
- **读** 或 **写** → 展示入口。

### 7.2 按钮级

| 场景 | 条件 |
|---|---|
| 提交类（发放、费率申请、积分配置提交…） | 对应 Tab = **写** |
| 审批通过/驳回 | 在该 **模块** 对应 **敏感组** 内，且为 **被派单处理人** |
| 体验金回收 | 在 **体验金 · 强制回收组** |
| 只读 Tab 内所有按钮 | 仅 **读** 时全部隐藏或禁用 |

### 7.3 代理返佣上限

运营人员在「一级代理管理」绑定时，输入比例 **≤** 该账号配置的返佣比例上限；超限前端校验 + 服务端拒绝。
