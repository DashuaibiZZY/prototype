## 1. 背景与目标

### 1.1 背景

ForX Admin 是面向内部运营、市场、风控、财务、产品等岗位的统一后台。各业务模块菜单不同，且存在大量「多人可进入同一页面、但可操作范围不同」的场景，例如：

- 体验金 **发放审批**：市场运营交叉、风控、老板依次或并行审批；
- 体验金 **数据查询&回收**：运营可查询与查看回收数据，仅风控可执行强制回收；
- 积分 **手动发放** 与 **积分审核**：提交人与各审批节点权限分离；
- 费率 **用户费率设置** 与 **费率审批**：配置人与审批人分离。

若按角色复制侧栏菜单（例如给市场单独做一个「体验金审批」菜单、给风控单独做一个「体验金回收」菜单），会导致菜单膨胀、职责边界模糊，且无法表达「同页不同按钮」的细粒度控制。

### 1.2 目标

| 目标 | 说明 |
|---|---|
| **统一权限模型** | 每个后台用户绑定 **一个角色**；角色通过 **权限矩阵** 配置「可见菜单 + 可执行操作」 |
| **可配置** | 产品/管理员可在 **权限与用户** 后台维护角色矩阵与人员，无需改代码 |
| **职责清晰** | 敏感操作（回收、提交审批、各级审批通过/驳回）单独授权，并在配置界面醒目标识 |
| **协作友好** | 同一业务页一个侧栏入口，通过 **操作权限** 区分审批节点与回收等能力 |
| **可审计** | 角色变更、用户变更、敏感操作均留痕（正式上线要求） |

### 1.3 非目标（本期不做）

- 单用户绑定多个角色、权限自动并集；
- 按代理树/数据行级别的 **数据范围** 过滤（列为二期）；
- 临时授权、代办委托、权限过期（列为二期）；
- 在原型业务页按角色隐藏 UI（原型刻意全量展示，见 §14）。

## 3. 名词解释

| 名词 | 定义 |
|---|---|
| **后台用户** | 可登录 ForX Admin 的内部账号（通常为企业邮箱） |
| **角色** | 权限的集合载体；一个用户 **只能** 绑定一个角色 |
| **菜单权限** | 控制左侧导航是否展示某业务入口；无菜单权限则无法通过正常导航进入该页 |
| **操作权限** | 控制页面内按钮、表单提交、审批动作等；可与菜单权限独立配置 |
| **敏感操作** | 对资金、用户权益或审批结论有实质影响的写操作；配置矩阵中用 **琥珀色** 标识，并在底部汇总展示 |
| **权限矩阵** | 以「业务模块 ×（菜单 + 操作）」checkbox 形式呈现的配置界面 |
| **内置角色** | 系统预置的 9 个岗位角色，不可删除，可改权限范围 |
| **自定义角色** | 管理员新建的角色，可删除；删除后原绑定用户降级为「测试」角色 |
| **管理员专属能力** | 仅「管理员」角色天然拥有、且 **不出现在权限矩阵** 的三项系统管理能力（见 §6） |
| **代理业务权限** | 代理中心内「运营权限配置」所管的返佣上限等业务数据权限，与本文 **Admin 功能权限** 并存，登录后合并生效 |

## 4. 总体方案

### 4.1 权限模型

```
后台用户（1 个角色） → 角色 → 权限集合（菜单可见 + 页面内可操作）
```

- **RBAC（基于角色的访问控制）**：不直接给用户勾权限，而是给用户指定角色，改角色即改一批人的能力。
- **单用户单角色**：不支持一人多角色；若岗位复合，应新建「复合角色」或在矩阵中调整该角色权限，而不是多绑。
- **菜单 + 操作双层**：  
  - 仅有 **操作权限** 而无 **菜单权限** 时，用户无法从侧栏进入（除非未来做深链，本期不开放）。  
  - 仅有 **菜单权限** 而无 **操作权限** 时，可进入页面只读或部分只读（视页面设计而定）。

### 4.2 多角色协作同一页的原则

**一个侧栏入口 + 不同操作权限**，不按角色复制菜单。

| 反例（不做） | 正例（做） |
|---|---|
| 侧栏同时有「体验金审批-市场」「体验金审批-风控」 | 侧栏仅「发放审批」；市场/风控/老板各自拥有对应 **审批操作** |
| 侧栏单独「体验金回收」 | 侧栏「数据查询&回收」；仅风控拥有 **强制回收** 操作 |

### 4.3 管理员「全部权限」

「管理员」角色视为拥有 **全部菜单 + 全部操作 + 管理员专属能力**。在权限矩阵中表现为全部勾选，并展示「全部权限」标签；保存时记为「全量授权」语义，便于与部分勾选角色区分。

## 5. ForX Admin 导航结构

所有后台模块共用 **统一左侧导航**，按业务分组如下：

| 模块分组 | 侧栏入口 |
|---|---|
| **系统** | 权限与用户 |
| **代理中心** | 一级代理管理、运营权限配置、佣金对账与发放 |
| **体验金** | 卡组配置、批量发放、发放审批、数据查询&回收、操作记录 |
| **风控冻结** | 用户冻结设置、冻结操作记录 |
| **排行榜** | 排行榜影子配置 |
| **费率** | 用户费率设置、费率审批、费率操作记录 |
| **积分** | 积分发放总览、每周积分总池设置、积分加成配置、用户积分查询、手动发放积分、积分审核、操作记录 |

**正式上线行为**：侧栏仅展示当前用户角色矩阵中已勾选 **菜单权限** 的入口。  
**原型行为**：侧栏 **固定展示全部入口**，便于产品、设计、研发对照文档走查；权限差异以本文档及「权限与用户」配置页为准（见 §14）。

## 6. 管理员专属能力（不进权限矩阵）

以下能力 **仅管理员角色** 默认拥有，**不在** 角色权限矩阵中展示，避免被误配给其他岗位：

| 能力 | 说明 |
|---|---|
| **进入「权限与用户」** | 访问系统 → 权限与用户配置页 |
| **管理角色矩阵** | 编辑各角色权限、新增/删除自定义角色、恢复默认配置 |
| **管理后台用户** | 新增、编辑、删除后台用户（系统内置超级管理员账号不可删） |

**产品规则**：其他角色即使被手工赋予全部业务菜单与敏感操作，也 **不能** 获得上述三项；只有「管理员」角色可以管理权限本身。

## 9. 权限与用户配置后台 · 功能需求

**入口**：ForX Admin → **系统** → **权限与用户**  
**使用人群**：仅管理员（§6）

### 9.1 页面框架

| 区域 | 内容 |
|---|---|
| 页头标题 | Tab 为「角色管理」时：**角色与权限**；Tab 为「后台用户」时：**后台用户** |
| 页头副标题 | 配置角色权限矩阵与后台用户（单用户单角色） |
| 顶栏 Tab | **角色管理** / **后台用户**（切换时更新 URL 锚点，刷新后保持 Tab） |
| 右上角操作 | **恢复默认配置**（见 §9.6） |
| 当前登录展示 | 展示当前登录者身份（如「管理员」） |

### 9.2 Tab：角色管理

#### 9.2.1 布局

左右分栏：

- **左侧（约 280px）**：角色列表  
- **右侧（自适应）**：选中角色的权限矩阵

#### 9.2.2 角色列表

| 元素 | 规则 |
|---|---|
| 角色卡片 | 展示：角色名称、**内置** / **自定义** 标签、说明文案、已配置权限数量（「全部」或「N 项」） |
| 选中态 | 蓝色边框高亮；选中后右侧矩阵同步该角色 |
| **+ 自定义** | 打开「新增自定义角色」弹窗（§9.2.5） |
| 底部提示文案 | 「内置角色不可删除；左侧选中角色后右侧配置权限范围」 |
| 空数据 | 提示「无角色数据，请点击恢复默认配置」 |

**内置角色（9 个，不可删除）**：管理员、运营、市场、测试、产品、风控、安全、财务、CEO。

#### 9.2.3 权限矩阵 · 标题区

| 元素 | 说明 |
|---|---|
| 主标题 | `{角色名} · 权限范围` |
| 副标题 | 角色说明文案 |
| 统计 | 部分授权时显示「已选 N / 全量 M 项」；全选时显示紫色 **「全部权限」** 标签 |

#### 9.2.4 权限矩阵 · 模块块

按 **§7** 的业务模块分组（代理中心、体验金、风控冻结、排行榜、费率、积分），每组包含：

| 元素 | 交互 |
|---|---|
| 模块标题栏 | 模块名称 + **全选本模块** / **取消全选**（切换该模块下所有菜单与操作 checkbox） |
| 菜单项 checkbox | 文案 + 灰色副标题「菜单可见」 |
| 操作项 checkbox | 文案 + 副标题「操作」或「敏感操作」；敏感项整行浅琥珀底色 |
| 敏感操作汇总 | 矩阵底部琥珀色区块，列出 §7.7 全部敏感项，已授权为实心标签，未授权为灰边标签 |

#### 9.2.5 权限矩阵 · 底栏操作

| 按钮 | 行为 |
|---|---|
| **重置** | 放弃当前未保存的编辑，恢复为上次保存的矩阵状态 |
| **保存角色权限** | 持久化当前勾选结果；toast/alert 提示「已保存「{角色名}」的权限配置」 |
| **删除角色** | 仅 **自定义角色** 显示；确认后删除角色，并将绑定该角色的用户改为「测试」角色 |

**保存规则**：

- 若矩阵中 **全部可配置项** 均被勾选，保存为「全量授权」语义（与管理员一致，但仍不获得 §6 三项，除非该用户角色就是「管理员」）。  
- 部分勾选则仅保存勾选项列表。

**管理员角色**：打开时矩阵默认全选；§6 三项不在矩阵中出现。

#### 9.2.6 弹窗：新增自定义角色

| 字段 | 必填 | 校验与说明 |
|---|---|---|
| 角色名称 | 是 | 不可为空，如「外包审核」 |
| 说明 | 否 | 角色用途描述 |
| 取消 | — | 关闭弹窗不保存 |
| 创建 | — | 创建成功后选中该角色，权限初始为空，需勾选后保存 |

### 9.3 Tab：后台用户

#### 9.3.1 列表区

顶部说明：「每个用户仅绑定 **一个** 角色；登录后菜单与敏感操作由该角色权限矩阵决定。」

右侧主按钮：**+ 新增后台用户**

#### 9.3.2 用户表格

| 列 | 说明 |
|---|---|
| 姓名 | 展示名 |
| 登录账号 | 企业邮箱 |
| 角色 | 当前绑定的唯一角色名称 |
| 状态 | **启用**（绿色标签）/ **停用**（灰色标签） |
| 最近登录 | 时间戳；无则「—」 |
| 操作 | **编辑**；**删除**（内置超级管理员「产品总监」不可删） |

#### 9.3.3 弹窗：新增 / 编辑后台用户

| 字段 | 必填 | 说明 |
|---|---|---|
| 姓名 | 是 | 展示名 |
| 登录账号（邮箱） | 是 | 新增时录入；编辑时可改 |
| 角色 | 是 | 下拉 **单选**，选项为当前全部角色（含自定义） |
| 取消 / 保存 | — | 保存后刷新列表 |

**校验**：姓名、账号不可为空；账号格式为企业邮箱。

**停用用户**：列表展示停用状态；正式上线后停用用户不可登录（原型可仅展示状态字段，登录拦截为 P1）。

### 9.4 恢复默认配置

| 项 | 说明 |
|---|---|
| 触发 | 右上角 **恢复默认配置** |
| 二次确认 | 文案：「恢复为默认角色与用户配置？自定义角色将丢失。」 |
| 效果 | 恢复 §8 全部内置角色默认权限 + §8.10 演示用户；**删除所有自定义角色** |
| 反馈 | 提示「已恢复默认配置」；角色列表回到「管理员」选中 |

### 9.5 异常与边界

| 场景 | 期望行为 |
|---|---|
| 本地配置损坏 / 角色列表为空 | 自动回退默认配置；或引导用户点击「恢复默认配置」 |
| 删除自定义角色 | 绑定用户 → **测试** 角色 |
| 删除后台用户 | 不可删除内置超级管理员 |
| 切换 Tab / 刷新 | URL 锚点 `#roles` / `#users` 与 Tab 一致 |

## 11. 审批协作与审批页 Tab（原型说明）

体验金 / 积分 / 费率 **审批子页** 顶部有 **市场运营交叉 / 风控 / 老板** Tab，用于原型演示不同审批节点的列表与按钮状态。

| 审批 Tab | 对应操作权限 |
|---|---|
| 市场运营交叉 | 各模块「交叉审批」 |
| 风控 | 各模块「风控审核」 |
| 老板 | 各模块「老板审批」 |

**正式上线**：根据登录用户 **实际拥有的操作权限** 决定可见节点与可操作按钮，**不依赖** Tab 切换模拟身份。用户仅能看到自己有权限的节点；若只有一个节点权限，可不展示 Tab 而直接展示对应列表。

## 12. 登录与身份

| 项 | 需求 |
|---|---|
| 账号体系 | 企业邮箱 + 密码或 SSO（与 ForX 内部账号体系对齐，P1 实现） |
| 登录响应 | 至少包含：用户 ID、姓名、**角色 ID/名称**、**展开后的权限列表**（含管理员专属三项判定） |
| 权限变更生效 | 用户 **重新登录** 或 token 刷新后生效；可选：强制踢下线（P2） |
| 单角色约束 | 给用户分配角色时仅允许单选；后端存储单一 `roleId` |

## 13. 与代理「运营权限配置」的关系

| 维度 | Admin 功能权限（本文） | 代理运营权限配置 |
|---|---|---|
| 作用对象 | ForX Admin 内部用户 | 代理商及其下级运营 |
| 控制内容 | 能否进入菜单、能否点审批/回收等 | 返佣比例上限、代理数据可见范围等 |
| 配置入口 | 系统 → 权限与用户 | 代理中心 → 运营权限配置 |
| 生效方式 | 登录 Admin 时合并校验 | 登录代理后台或 Admin 代理模块时生效 |

**产品原则**：两类权限 **同时生效**，互不替代；给运营同学开 Admin「运营权限配置」菜单 ≠ 自动拥有体验金回收能力。

## 14. 原型与正式上线差异

| 维度 | 交互原型（当前） | 正式上线（目标） |
|---|---|---|
| 业务页 UI | **全量展示**所有菜单、按钮 | 按登录用户权限显隐 |
