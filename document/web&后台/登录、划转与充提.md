# 登录、划转与充提

## 文档说明

本文档描述 ForX 平台账户登录、站内划转、充值与提现的完整产品需求与业务规则。平台底层钱包与链上能力由第三方合作伙伴提供，我方研发负责前端交互、后台业务逻辑以及与第三方的接口对接。  

文中“第三方”指提供链上钱包管理、地址生成、交易监听、转账执行等服务的合作伙伴。

原型（Web 交互完整原型）：[投资组合.html](https://dashuaibizzy.github.io/prototype/perp_dex/投资组合.html)

导航栏中钱包入口的挂载位置详见《[导航栏](导航栏.md)》§3.5。

## 1\. 登录模块



### 1\.1 模块概述

- **目标**：为用户提供安全的身份认证机制，将链上地址或邮箱与统一账户（UID）绑定，建立可管理的会话（Session），并控制后续资产操作权限。

- **核心登录方式**：

    - **钱包登录**：基于 Privy SDK 实现钱包连接与签名验证。

    - **邮箱登录**：邮箱验证码登录（由第三方邮件服务发送 6 位验证码）。

- **账户体系设计**（与 App 端对齐）：

    - 平台以 **UID** 作为唯一账户标识，资产、仓位、订单、账单等数据均归属于该 UID。

    - 支持两种**互斥**登录方式：**钱包登录**（连接外部钱包）或 **邮箱登录**（邮箱验证码）。用户选定一种方式完成登录后，**不支持**再绑定或切换为另一种登录凭据（不提供「钱包登录后绑邮箱」「邮箱登录后绑外部钱包」）。

    - **钱包登录**：UID 与当前连接的外部钱包地址关联；账户信息仅展示该钱包地址。

    - **邮箱登录**：UID 与邮箱关联；平台通过 Privy 等为该 UID **自动生成**链上钱包地址（用于充提等），该地址在 UI 上与「外部钱包连接」不是同一概念。

    - 身份验证器 App（TOTP）仅对**邮箱登录**用户开放绑定与管理；钱包登录用户不展示相关入口。

        

### 1\.2 登录入口与方式选择

- **入口**：导航栏右侧「连接钱包」按钮（未登录）；已登录后为钱包地址或邮箱摘要 + 下拉箭头。

- **弹窗**：居中 Modal「登录 / 注册」，**非**选项卡切换，结构为：

    1. **邮箱登录区**（上方）：邮箱输入 → 发送验证码 → 6 位验证码 → 登录

    2. **分隔线**：`OR`

    3. **钱包登录区**（下方）：钱包列表（MetaMask、OKX Wallet 等），点击即连接并完成登录

- **不提供**登录后的「绑定邮箱」「绑定外部钱包」弹窗或模式。

        

### 1\.3 钱包连接登录流程

#### 1\.3\.1 触发与选择

1. 用户点击“连接钱包”按钮。

2. 前端弹出钱包选择弹窗，展示支持的钱包列表（MetaMask、OKX Wallet 等）。

3. 用户点击目标钱包项。

    

#### 1\.3\.2 连接与地址获取

1. 前端调用 Privy SDK 或相应连接器，唤起浏览器钱包插件。

2. 用户在钱包插件中确认连接。

3. 前端获得用户钱包公钥地址。

    

#### 1\.3\.3 身份验证（签名登录，防重放）

1. **获取 nonce**：前端调用后端接口 `GET /auth/nonce`，服务端返回一次性随机数 nonce，包含过期时间（如 5 分钟）和绑定域名。

2. **发起签名**：前端引导钱包对包含 nonce 的文本（如 “ForX Login: nonce=xxx, domain=forx\.com”）进行签名。

3. **提交验证**：前端将 `{ address, signature, nonce }` 发送至 `POST /auth/login/wallet`。

4. **后端验证**：

    - 通过公开地址恢复签名者公钥，验签通过。

    - 检查 nonce 未过期、未被使用过、域名匹配。

    - 验证通过后，建立用户会话，标记该 nonce 已使用。

        

#### 1\.3\.4 账户处理与会话建立

- **新钱包地址**：后端创建新 UID，绑定该钱包地址，初始化空资产数据。

- **已知钱包地址**：直接登录，关联已有资产、持仓、订单、积分等。

- **地址已绑定至其他 UID**：高级合并场景，当前版本暂不自动处理，提示“该地址已被绑定”（后续迭代可支持安全验证合并）。

- 后端生成 JWT 或设置 HttpOnly Session Cookie，有效期 **7 天**。

- 前端存储凭证，后续请求自动携带。

    

#### 1\.3\.5 界面状态更新

- 登录弹窗自动关闭。

- 导航栏按钮变为钱包地址脱敏显示（如 `0xd593...2Dd2`），鼠标悬停或点击可展开下拉菜单。

- 行情页、资产页等刷新为用户个人数据。

    

### 1\.4 邮箱登录流程

#### 1\.4\.1 交互步骤

1. 用户选择“邮箱登录”选项卡。

2. 输入邮箱地址，点击“获取验证码”。

3. 前端请求 `POST /auth/send-code`，携带邮箱地址。

4. 后端调用第三方邮件服务发送 **6 位数字验证码**，有效期 5 分钟，同一邮箱 60 秒内不可重复发送。

5. 用户收到邮件后输入验证码，点击“登录”。

6. 前端调用 `POST /auth/login/email`，携带邮箱和验证码。

7. 后端校验验证码正确且未过期。

8. 验证通过后，进入账户处理与会话建立。

    

#### 1\.4\.2 账户处理与会话建立

- **新邮箱**：创建新 UID，绑定该邮箱。

- **已有邮箱**：直接登录，加载该 UID 下的所有数据。

- 会话同样为 **7 天** 有效期，下发凭证。

    

#### 1\.4\.3 界面更新

- 导航栏显示邮箱脱敏前缀（如 `user***@mail.com`），点击展开下拉菜单。

    

### 1\.5 登录态下的账户信息展示（Web 下拉浮窗）

与 App 个人资料页信息模型对齐，**不提供**登录后交叉绑定。

#### 1\.5.1 顶栏入口

| 登录方式 | 顶栏按钮文案 |
|---|---|
| 钱包登录 | 简化钱包地址（如 `0xd593...2Dd2`） |
| 邮箱登录 | 登录邮箱 |

悬停展开下拉浮窗；绿色状态点表示已登录。

#### 1\.5.2 下拉浮窗结构

自上而下：

1. **UID 行**：FX 头像块 + `UID: {uid}` + **右侧复制图标**（复制完整 UID）
2. **账户信息区**（见下表）
3. **总资产价值**：估值卡片（如 `$12,450.50`）
4. **快捷操作**：充值、提现、划转（三列按钮）
5. **导出邮箱钱包**（仅邮箱登录，见 §1.11）
6. **退出登录**

| 行 | 钱包登录 | 邮箱登录 |
|---|---|---|
| 邮箱 | 不展示 | 邮箱 + 复制图标 |
| 钱包 | 钱包地址 + 复制图标 | Privy 钱包地址 + 复制图标 |
| 身份验证器 | 不展示 | 状态 + 绑定/管理入口（见 §1.10） |

**复制交互**：UID、邮箱、钱包行均在最右侧提供复制图标；点击复制**完整值**（非缩略展示），Toast「已复制」。

#### 1\.5.3 多凭据绑定（已废弃）

~~一个 UID 绑定邮箱 + 钱包、登录后弱引导交叉绑定~~ — **当前产品不支持**。若历史文档或接口仍描述「绑邮箱 / 绑钱包」，以本节与 §1.1 互斥模型为准。

#### 1\.5.4 账户合并场景（预留）

若用户使用已关联其他 UID 的凭据尝试登录，提示「该凭据已关联其他账户」，不提供自动合并（后续版本可单独设计）。

### 1\.6 保持登录状态与自动恢复

- 页面刷新或重新打开时，前端检测本地是否存在有效 Token。

- 若存在，静默调用 `/auth/check-session` 接口验证有效性。

- 有效则直接恢复登录态，展示个人数据；无效则清除本地凭证，显示未登录状态。

    

### 1\.7 退出登录

- **入口**：导航栏下拉菜单中的“退出登录”。

- **操作结果**：

    - 调用 `/auth/logout` 使服务端 Session 失效。

    - 清除前端存储的 Token 与用户缓存。

    - 界面重置为未登录状态。

- **解除绑定**：需在账户安全设置中操作，与退出登录无关。

    

### 1\.8 登录日志

系统需记录每一次登录操作，用于安全审计与用户自查，日志字段包括：

- 登录时间

- IP 地址

- 设备信息（User\-Agent）

- 登录方式（wallet / email）

- 登录凭据标识（钱包地址或邮箱）

- 登录结果（success / fail / blocked）

- 失败原因（如 nonce expired, signature invalid）

    

### 1\.9 异常处理

|异常场景|处理方式|
|---|---|
|用户未安装所选钱包|弹出提示并引导至该钱包官方下载页|
|用户在钱包弹窗中拒绝连接|登录弹窗不关闭，顶部显示浅红色提示：“授权失败，请重试”|
|用户在签名步骤拒绝签名|同上，“签名已取消，请重试”|
|nonce 过期|提示“登录信息已过期，请重新发起”，重新生成 nonce|
|签名验证失败|提示“签名验证失败，可能存在篡改，请重试”|
|邮箱验证码错误|输入框标红，提示“验证码错误，请重新输入”|
|邮箱验证码过期|提示“验证码已过期，请重新获取”|
|邮箱已被其他 UID 绑定|提示“该邮箱已绑定其他账户，请使用其他邮箱或联系客服”|

### 1\.10 身份验证器 App（Web 居中 Modal）

**适用范围**：仅**邮箱登录**用户；钱包登录不展示入口。

**技术标准**：TOTP（RFC 6238）；6 位动态码，30 秒周期；兼容 Google Authenticator、Microsoft Authenticator 等。

**入口**：用户信息下拉浮窗 · 身份验证器行

| 状态 | 展示 | 操作 |
|---|---|---|
| 未设置 | 琥珀色「未设置」 | 文字链「绑定」 |
| 已绑定 | 绿色「已绑定」 | 文字链「管理」 |

**交互形态**：Web **居中 Modal**（与充提弹窗一致）：标题 + 子步骤 **← 返回** + **✕ 关闭**。

**状态机**（与 App 端能力对齐）：

```Plain Text
未绑定 → 引导 → 扫码/密钥 → 验证码确认 → 已绑定
已绑定 → 修改（验证旧码 → 重新绑定）/ 移除（风险提示 + 动态码）→ 未绑定
```

| 步骤 | 标题 | 要点 |
|---|---|---|
| 未绑定引导 | 身份验证器 App | 说明 +「立即绑定」 |
| 扫码/密钥 | 绑定验证器 | QR、手动密钥、复制密钥、「下一步」 |
| 验证码确认 | 验证绑定 | 6 位动态码、「确认绑定」 |
| 已绑定管理 | 身份验证器 App | 状态卡、修改验证器、移除验证器 |
| 修改 | 修改验证器 | 验证旧码 → 重新走绑定流程 |
| 移除 | 移除验证器 | 红色风险提示 + 动态码 + 确认移除 / 取消 |

绑定成功后：下拉状态同步；提现等安全场景可使用身份验证器动态码（见 §2.2）。

### 1\.11 导出邮箱钱包（Web 居中 Modal）

**入口**：用户信息下拉 ·「导出邮箱钱包」整行（带导出图标）。**仅邮箱登录**展示。

**流程**：安全验证 → Export wallet 内容页（同 Modal 内步骤切换）。

**步骤 A · 安全验证**

| 身份验证器 | 验证方式 |
|---|---|
| **未绑定** | 向当前登录邮箱发送验证码 → 用户输入 6 位邮箱验证码 →「验证并继续」 |
| **已绑定** | 输入身份验证器 6 位动态码 →「验证并继续」 |

验证失败：行内错误提示，不进入导出页。

**步骤 B · Export wallet**

| 区域 | 内容 |
|---|---|
| 标题 | Export wallet |
| 说明 | Copy either your private key or seed phrase to export your wallet. **Learn more**（外链） |
| 安全提示 | Never share your private key or seed phrase with anyone.（醒目提示块） |
| Your wallet | 钱包地址缩略（如 `0x972...0E79`）+ 复制图标（完整地址） |
| 按钮 | **Copy key**（私钥）、**Copy Phrase**（助记词/种子短语） |

私钥与助记词仅在验证通过后通过复制按钮输出；未验证不得展示敏感信息。

## 2\. 权限与安全策略（按登录方式区分）

### 2\.1 充值、提现权限差异（Web 入口）

平台根据**当前会话登录方式**控制充值/提现 Modal 的首屏选项（原型见投资组合页）：

| 操作 | 钱包登录 | 邮箱登录 |
|---|---|---|
| 充值 | 可选「从已连接钱包充值」或「从外部钱包/交易所充值」 | 仅「外部充值」（展示充值地址 / QR） |
| 提现 | 可选「提现至已连接钱包」或「提现至外部地址」 | 仅「提现至外部地址」 |

后端权限、风控与链上执行仍按账户 UID 与第三方能力处理；上表为 **Web 产品入口** 差异。

|操作场景|钱包登录|邮箱登录|
|---|---|---|
|充值\-连接钱包充值|✅ 可用|❌ 入口不展示|
|充值\-外部地址充值|✅ 可用|✅ 可用|
|提现\-至已连接钱包|✅ 可用|❌ 不可用|
|提现\-至外部地址|✅ 可用|✅ 可用|
|提现安全验证|钱包签名|身份验证器 \+ 邮箱验证码（须已绑验证器，见 §2.2）|



### 2\.2 提现安全验证规则细则

- **钱包登录**：

    - 提现安全验证使用 **钱包签名**。

    - 签名消息需包含提现关键信息（目标地址、链、金额、时间戳等）。

    - 签名通过后进入**二次确认弹窗**（链、接收地址、金额、手续费、预计到账、到账时间），用户确认后提交。

- **邮箱登录**：

    - 须已绑定**身份验证器 App**（见 §1.10）；未绑定时拦截提现并引导打开绑定 Modal。

    - 外部地址提现：填写地址与金额后，弹出**安全验证** Modal — 身份验证器动态码 + 邮箱验证码（可获取验证码）。

    - 验证通过后进入**提现确认**弹窗，确认后提交。

- ~~邮箱\+钱包均已绑定、降级验证等~~ — 当前产品为登录方式互斥，不适用。

        

### 2\.3 身份验证器绑定规则

- **展示范围**：仅邮箱登录用户（§1.10）。

- **提现关联**：邮箱登录用户未绑验证器时不可完成外部地址提现（可先引导绑定）。

- **绑定 / 修改 / 移除**：Web Modal 全流程见 §1.10；绑定后服务端保存 TOTP secret，提现与导出钱包等场景校验动态码。

- **钱包登录用户**：不展示身份验证器入口；提现依赖钱包签名。

## 3\. 划转模块

本平台存在两类「划转」能力，勿混淆：

| 类型 | 说明 | Web 原型 |
|---|---|---|
| **站内账户划转** | 同一 UID 下 **资金账户** 与 **交易账户** 之间调拨 USDT | 投资组合页「资金划转」Modal |
| **用户间划转** | 将资产划转至另一 ForX 用户（见 §3.4，若产品启用） | — |

### 3\.1 站内账户划转（资金账户 ↔ 交易账户）

#### 3\.1.1 功能概述

- 同一用户 UID 下，在**资金账户**与**交易账户**之间划转 USDT，站内即时到账，无链上操作、无手续费。

- 须已登录；未登录点击入口提示先登录。

#### 3\.1.2 入口

- 导航栏用户下拉 ·「划转」按钮

- 投资组合页资产卡片区 ·「划转」按钮

#### 3\.1.3 交互（Web 居中 Modal）

| 区域 | 说明 |
|---|---|
| 标题 | 资金划转 |
| 方向 | 「从」账户 + 「到」账户，中间**切换方向**按钮（默认：资金账户 → 交易账户） |
| 资产 | 选择资产（默认 USDT） |
| 数量 | 输入划转数量；展示可用余额；支持「全部」 |
| 提交 | 「确认划转」 |

提交成功：Toast 或提示「划转成功」，关闭 Modal，刷新账户余额展示。

#### 3\.1.4 校验

- 划转数量 > 0 且 ≤ 转出账户可用余额。

- 转出账户资金未被风控冻结（与现有资金冻结规则一致）。

### 3\.2 用户间划转（平台用户转账）

#### 3\.2.1 功能概述

- 支持用户将平台账户内未冻结的资产划转给**另一个** ForX 平台账户（与 §3.1 站内账户划转不同）。

- 资产类型：USDT（可扩展）；站内实时到账，零手续费，不经过链上。

#### 3\.2.2 入口与交互流程

1. **入口**：资产总览页等（若产品单独提供用户间划转入口）。

2. **弹窗输入**：

    - 接收方标识：支持输入邮箱或 UID。

    - 币种：默认 USDT。

    - 金额：手动输入，不得超过可用余额。

    - 备注（选填）。

3. **提交前校验**：

    - 接收方是否存在且账户状态正常（非冻结）。

    - 发送方余额充足。

    - 安全验证（可配置是否需要 2FA，默认与提现安全等级对齐或降低，此处暂定：若当前会话已钱包连接，需钱包签名；否则需邮箱验证码）。

4. **提交后处理**：

    - 发送方余额即时扣减。

    - 接收方余额即时增加。

    - 记录划转订单，生成划转 ID。

    - 双方均收到站内通知（资产变动提醒）。

        

### 3\.3 用户间划转记录

划转记录展示字段：

- 划转 ID

- 发送方 UID

- 接收方标识（邮箱脱敏/UID）

- 币种

- 金额

- 手续费（0）

- 状态（成功 / 失败）

- 时间

    

### 3\.4 用户间划转异常处理

- 接收方不存在或已冻结：提示“对方账户不存在或已冻结，无法划转”，资金不动。

- 余额不足：前端即时报错。

- 安全验证失败：提示并停留在当前页，划转不提交。

## 4\. 充值模块



### 4\.1 模块说明

- **核心功能**：用户将外部链上 USDT 转入平台账户。

- **支持链**：Ethereum、Arbitrum、Polygon、Base、Optimism、SOL、TRON

- **依赖**：充值地址生成、交易监听、入账确认均由第三方提供，我方负责展示与记录。

    

### 4\.2 充值方式选择（Web Modal）

- **钱包登录**：首屏两个入口 —「从已连接钱包充值」「从外部钱包/交易所充值」。

- **邮箱登录**：直接进入「外部充值」页（资产、链、充值地址 QR、复制地址、到账时间说明、「完成」关闭）。

- 子步骤支持 **← 返回** 与 **✕ 关闭**（与投资组合页充提 Modal 一致）。

        

### 4\.3 从已连接钱包充值

#### 4\.3\.1 页面功能

- **链选择**：下拉框，列出支持的链，切换时刷新钱包余额。

- **数量输入**：手动输入或点击“最大”自动填充钱包内该链上 USDT 余额。

- **可用余额**：实时查询已连接钱包的链上 USDT 余额（非平台余额）。

- **确认按钮**：“确认充值”。

    

#### 4\.3\.2 交互流程

1. 用户输入数量，点击“确认充值”。

2. 前端构建 USDT 合约的 `transfer` 交易，目标地址为由第三方提供的平台充值合约地址或归集地址（需与第三方约定）。

3. 唤起钱包，请求用户确认交易并支付 Gas。

4. 用户确认后，前端获取 txHash，调用后端接口上报该充值交易 `POST /deposit/wallet`，携带 txHash、链、金额、钱包地址等。

5. 前端弹窗提示“充值申请已提交，预计 5～15 分钟内到账”，页面进入等待状态。

6. 后端将交易信息记录，并等待第三方通知确认状态。

    

### 4\.4 从外部钱包/交易所充值

#### 4\.4\.1 页面功能

- **链选择**：下拉框，切换时更新充值地址与说明。

- **充值地址展示**：清晰显示该用户在该链的唯一充值地址（文本 \+ 二维码），数据从第三方获取。

- **温馨提示**：展示最小充值金额、所需确认数、仅接收 USDT 等说明信息（内容由第三方提供）。

- **一键复制**：点击地址复制，反馈“已复制”。

- **完成按钮**：关闭弹窗，后台继续监听。

    

#### 4\.4\.2 业务需求（底层能力要求，由第三方满足）

|能力域|业务需求描述|
|---|---|
|充值地址生成|用户首次进入某链外部充值页时，第三方需为该用户生成唯一充值地址并与 UID 绑定。不同链的地址相互独立|
|地址生命周期|地址一经生成，永久绑定该用户，不可回收。账户冻结时仍可保留记录，但可停止入账|
|充值监听|第三方监控所有分配的充值地址上的 USDT 转账事件|
|入账确认|交易达到要求的确认数后，第三方通知我方入账，携带 txHash、金额、确认数、链等|
|异常识别|低于最小充值额、非 USDT 资产、重复 txHash、链上失败等异常情况需在回调中标明|



#### 4\.4\.3 第三方需提供的数据

- 充值地址（每用户每链）

- 链、币种信息

- 最小充值金额

- 所需确认数

- 区块浏览器地址模板（用于拼接 txHash 链接）

- 充值状态回调接口

    

### 4\.5 充值状态定义

我方根据第三方推送维护以下充值状态：

|状态|含义|用户可见性|
|---|---|---|
|`pending`|交易已上链，但尚未达到所需确认数|是，显示“确认中”|
|`confirmed`|已达到确认数，资金已入账，余额增加|是，显示“已到账”|
|`failed`|链上交易执行失败（如合约错误、Gas不足导致回滚）|否（后台可见，前端可显示“充值失败”）|
|`invalid`|交易不符合入账条件（如金额低于最小充值额、非USDT）|否（后台记录，客服介入）|

用户侧状态流转：`pending` → `confirmed`（失败或异常交易不在前端展示为正常记录）。



### 4\.6 充值记录与展示

- 充值记录列表需展示：时间、币种、链、金额、txHash、状态。

- 提供 txHash 跳转链接，链接根据第三方提供的区块浏览器模板拼接，如 `https://etherscan.io/tx/{txHash}`。

## 5\. 提现模块



### 5\.1 模块说明

- **核心功能**：用户将平台账户内的 USDT 提现至外部 EVM 地址。

- **支持链**：与充值相同。

- **依赖**：提现交易构造、广播、状态监控由第三方执行，我方负责前端交互、安全验证及状态同步。

    

### 5\.2 提现方式选择（Web Modal）

- **钱包登录**：首屏 —「提现至已连接钱包」「提现至外部账户」。

- **邮箱登录**：仅「提现至外部地址」表单（资产、链、接收地址、数量、手续费与预计到账展示）。

- 邮箱登录外部提现：提交前须身份验证器 + 邮箱验证码（§2.2）；钱包登录走签名 + 二次确认弹窗。

        

### 5\.2.1 模块入口说明

### 5\.3 提现至已连接钱包

#### 5\.3\.1 页面功能

- 链：下拉选择。

- 数量：手动输入或点击“最大”填充平台可用提现余额。

- 可用余额：平台内可用提现余额（已扣除保证金等，具体逻辑沿用现有系统）。

- 接收地址预览：展示当前连接钱包的完整地址（只读）。

- 网络手续费：展示预估手续费（从第三方获取并叠加平台溢价）。

- 预计到账金额：`提现金额 - 手续费`，实时计算显示。

    

#### 5\.3\.2 交互流程

1. 用户填写信息，点击“确认提现”。

2. **余额检查**：前端校验提现金额 ≤ 可用余额，否则报错。

3. **后端校验**：提交到后端进行风控规则校验（见第6节），地址风险检查。

4. **安全验证（钱包签名）**：风控通过后，后端生成提现指令（含目标地址、金额、链、时间戳等），前端唤起钱包要求用户签名。

5. **二次确认弹窗**：签名后弹出确认弹窗，展示完整提现信息（链、地址、金额、手续费、到账金额、预计到账时间），用户再次确认。

6. 确认后，签名提交至后端，后端验证签名，调用第三方提现接口提交请求。

7. 第三方返回接受状态，后端将提现记录置为 `processing`，页面提示“已申请提现”，用户可查看记录。

    

### 5\.4 提现至外部地址

#### 5\.4\.1 页面功能

与提现至钱包一致，但多一个**地址输入框**，用户需手动输入 EVM 地址。



#### 5\.4\.2 交互流程

1. 用户输入地址、链、金额，点击“确认提现”。

2. **前端地址格式校验**：校验以 `0x` 开头的 42 位十六进制字符，不符则标红提示。

3. **后端校验**：校验地址格式、是否为合约地址（可配置是否允许）、是否在黑名单、是否与所选链匹配（需第三方提供链与币种匹配关系）。

4. **余额检查、风控检查**（同钱包提现）。

5. **安全验证**：按 2\.2 规则执行（钱包签名 或 GA\+邮箱验证码）。

6. **二次确认弹窗**：内容强调外部地址不可逆，用户确认后提交。

7. 后续流程同钱包提现。

    

### 5\.5 提现状态定义

我方维护的提现状态机，融合内部风控与第三方回调：

|状态|说明|用户可见|
|---|---|---|
|`created`|提现申请已创建，等待风控审核|否，前端展示“处理中”或“待审核”|
|`pending_risk_review`|触发人工审核，等待运营处理|是，显示“审核中”|
|`risk_rejected`|风控审核未通过，提现被拒绝（终态）|是，显示“已拒绝”|
|`approved`|风控通过，已发送至第三方等待广播|否，内部状态|
|`processing`|第三方已广播交易，等待链上确认|是，显示“处理中”并附 txHash|
|`completed`|链上交易已确认，提现成功（终态）|是，显示“已完成”|
|`failed`|链上交易失败，资金需退回（终态）|是，显示“失败”并可查看原因|



状态流转路径：

- 正常流程：`created` → `approved` → `processing` → `completed`

- 人工审核：`created` → `pending_risk_review` → `approved` 或 `risk_rejected`

- 链上失败：`processing` → `failed`

    

### 5\.6 提现失败处理

- 收到第三方 `failed` 回调（含失败原因如 out of gas、合约 revert 等）后：

    - 后端自动将提现时冻结的金额解冻，恢复至用户可用余额。

    - 更新提现记录为 `failed`，记录失败原因。

    - 前端提现详情页展示失败状态与原因，通知用户。

        

### 5\.7 提现手续费与定价

- **数据源**：第三方提供各链实时 Gas 预估（Gas Price、预估 Gas Limit），我方按配置的上浮系数（如 1\.1 倍）计算最终手续费。

- **手续费扣除方式**：从提现金额中直接扣除，用户收到的链上金额 = 提现金额 \- 手续费。

- **展示要求**：提现页面实时展示手续费和预计到账金额；二次确认弹窗中再次明确。

- **极端波动熔断**：当第三方反馈的 Gas Price 超过预设阈值（如近 10 分钟均值的 3 倍），系统自动暂缓普通优先级提现广播，等待 Gas 回落或转为人工处理。

## 6\. 充提开关与异常处理

### 6\.1 充提功能开关

管理后台需提供以下维度的功能开关，开关关闭后前端相应入口隐藏或置灰：

- **按链开关**：可紧急暂停某条链的充值/提现。

- **按币种开关**：可单独关闭 USDT 充提。

- **按用户风控状态**：对特定用户（如黑名单、风险账户）禁用充值或提现。

    

### 6\.2 异常充提处理规则引擎

|异常类型|处理动作|
|---|---|
|充值金额 \< 最小充值额|不入账，记录异常，前端可提示用户补足金额|
|充入错误链/币种|不入账，记录，联系客服人工处理|
|重复 txHash|拒绝入账，防止双花，记录告警|
|风控命中（第三方标记）|冻结该笔交易，告警|
|提现链上失败|自动解冻退回余额，记录失败原因|

所有异常均需记录详细日志并触发内部告警。

## 8\. 附录：用户操作流程速览

### 登录

- **钱包登录**：登录 Modal → 选择钱包 → 连接 → 签名 → 登录成功（仅钱包地址展示）

- **邮箱登录**：登录 Modal → 邮箱验证码 → 登录成功（邮箱 + Privy 钱包地址）

- **不支持**登录后交叉绑定邮箱/外部钱包

### 账户安全（邮箱登录）

- **身份验证器**：下拉入口 → Web Modal 绑定 / 修改 / 移除

- **导出邮箱钱包**：下拉入口 → 邮箱码或验证器码验证 → Export wallet（Copy key / Copy Phrase）

    

### 充值

- **钱包直充**（需连接钱包）：选链 → 输入数量 → 钱包确认交易 → 等待链上确认

- **外部充值**：选链 → 获取充值地址 → 在外部钱包转账 → 等待入账

    

### 提现

- **至已连接钱包**：选链 → 输金额 → 钱包签名 → 二次确认 → 提交 → 等待链上处理

- **至外部地址**：选链 → 输地址 → 输金额 → 安全验证（签名或 身份验证器+邮箱码）→ 二次确认 → 提交

- **邮箱登录**：须已绑身份验证器方可提现

    

### 划转

- **站内（资金 ↔ 交易）**：选择方向 → 输入金额 → 确认划转（导航栏或投资组合页入口）

- **用户间**（若启用）：输入对方标识 → 输入金额 → 安全验证 → 即时到账
