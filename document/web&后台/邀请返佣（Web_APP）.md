## App 页面路由（按用户类型）

App 端**不**在「邀请返佣」页内区分普通用户 / 合伙人两种 UI 平铺状态，而是根据登录用户的**角色标识**在路由层分流：

| 用户类型 | App 进入页面 | 说明 |
|---|---|---|
| **普通用户** | `app/邀请返佣.html` | 本文 **§App 页 · 邀请返佣** 全文适用 |
| **合伙人（代理）用户** | `app/代理中心.html` | 合伙人管理中心；邀请链接、团队、数据、佣金等均在独立模块中展示，**不进入**邀请返佣页 |

**典型入口**（奖励页、个人中心等）在用户点击「邀请返佣 / 合伙人中心」类入口时，客户端先读取角色：

| 入口 | 普通用户 | 合伙人 |
|---|---|---|
| 首页 · 「邀请」快捷入口 | `app/邀请返佣.html` | `app/代理中心.html` |
| 个人中心 · 「邀请赚币」 | `app/邀请返佣.html` | `app/代理中心.html`（个人中心不再重复展示独立「合伙人中心」入口） |
| 奖励页 · 「邀请返佣」卡片 | 展示等级进度；进入邀请返佣页 | **隐藏**等级进度；进入合伙人管理中心 |

1. 普通用户 → 打开邀请返佣页  
2. 合伙人用户 → 直接打开合伙人管理中心  

**与 Web 的差异**：

- **Web**：合伙人访问邀请返佣 URL 时默认重定向至代理中心；若强行进入则展示占位态（见 §普通用户 / 代理用户角色分离 · Web 端）。  
- **App**：合伙人用户**不出现**邀请返佣占位页；原型 `app/邀请返佣.html` 仅平铺普通用户及弹窗叠加态（分享海报、说明浮窗等），不含「合伙人用户」状态框。

合伙人 App 页面各模块需求见《[邀请合伙人无限层返佣系统](邀请合伙人无限层返佣系统.md)》**§4 用户合伙人中心（App）**（与 Web §3 业务口径一致，本文不再单独展开）。

### 等级配置表

系统根据用户的推广表现自动分配等级，返佣比例直接作用于受邀人产生的手续费

|等级|手续费返佣|升级门槛 (需同时满足)|备注|
|---|---|---|---|
|Lv 0|10%|无 (默认等级)|注册即拥有|
|Lv 1|15%|3位活跃好友 + 累计好友交易量 ≥ $2.5M|初级合作伙伴|
|Lv 2|20%|5位活跃好友 + 累计好友交易量 ≥ $5M|中级合作伙伴|
|Lv 3|25%|10位活跃好友 + 累计好友交易量 ≥ $10M|高级合作伙伴|

### 核心指标定义

1. **活跃好友**：

    - 必须是通过该用户邀请码注册的直邀用户

    - **有效判定标准**：过去30日交易额 ≥ 10,000

2. **交易量**：

    - 计算该用户下所有直邀好友产生的 **累计交易额**

    - 单位统一折算为 USDT

### 后端每日 00:00（UTC+8）更新\+结算机制

系统在每天 00:00:00 \(UTC\+8\) 触发自动化任务，顺序执行“结算”与“等级更新”。

**核心限制**：

- 前一自然日（T\-1日）及更早产生的未结算返佣，其**计算比例不受今日（T日）等级变更的影响**。

- 即：等级更新不回溯，所有历史返佣按产生交易时的用户等级锁定。

#### 3\.1 处理流程

1. **收益结算与锁定（优先级最高）：**

    - 抓取全站用户在 **昨日 00:00（UTC+8）** 至 **今日 00:00（UTC+8）** 之间产生交易的所有邀请关系。

    - 按照昨日（T\-1日）每个用户的实际等级和对应返佣比例，计算并锁定这一时间段产生的待结算返佣。

    - 将锁定后的返佣金额计入用户“待结算收益”，等待后续发放。

2. **等级快照与升级判断：**

    - 完成昨日收益锁定后，获取所有用户的实时邀请关系网和指标。

    - 重新统计每个用户的“活跃好友数”与“好友总交易量”。

    - 对照【等级配置表】，判断用户当前应属等级。

3. **等级更新：**

    - 若应属等级 \> 用户当前等级，则实时升级并记录升级时间。

    - 当系统判定用户当前应属等级 \< 用户现有等级时，不立即降级，而是进入 “7日缓冲期” 保护状态。

    - 缓冲期机制：

        - 触发条件：每日 **00:00（UTC+8）** 等级快照发现不满足当前等级门槛。

        - 保护状态持续 7 个自然日（自触发之日起算，含当日）。

        - 保护期内：

            - 用户等级与返佣比例暂时保持不变，仍按原高等级计算新交易的返佣。

            - 系统每日 **00:00（UTC+8）** 重新评估，若仍不满足则继续消耗缓冲期，若重新达标则缓冲期自动清除，等级不变。

        - 缓冲期结束后（第 8 日 **00:00（UTC+8）**）：

            - 若仍不满足条件，执行降级，更新等级与返佣比例。

            - 降级后，若后续再次达标，可重新升级。

        - 消息中心推送内容设计：

        - 节点一：触发缓冲期（第1天）

        - 标题：你的邀请等级保护已开启
        正文：近期活跃好友或交易量暂未达标，我们将为你保留当前返佣比例 7 天，抓紧邀请好友交易吧。

        ---

        - 节点二：缓冲期倒计时预警（第5天）

        - 标题：邀请等级保护还剩 3 天
        正文：若到期仍未恢复条件，返佣比例将从 x% 降至 y%。别让等级溜走，现在就邀请邀请好友交易吧。

        ---

        - 节点三：缓冲期倒计时预警（第7天）

        - 标题：邀请等级保护还剩 24 小时
        正文：若到期仍未恢复条件，返佣比例将从 x% 降至 y%。别让等级溜走，现在就邀请邀请好友交易吧。

        ---

        - 节点四：执行降级（第8天）

        - 标题：邀请等级已调整
        正文：返佣比例已从 x% 调整为 y%。继续邀请好友提升交易量，随时可以升回来。

    - 更新后的等级，从今日（T\+1 日）**00:00（UTC+8）** 起生效。

4. **生效范围：**

    - 今日 **00:00（UTC+8）** 后产生的新交易，将按更新后的等级计算返佣。

    - 昨日及之前已锁定的返佣，不再受此次等级变动影响。

#### 3\.2 举例说明

假设用户 Alice 在 6月7日 等级为 10% \(Lv1\)：

- 6月7日 23:00，好友 Bob 产生 $1000 交易，应获 $100 返佣（待结算）。

- 6月8日 **00:00（UTC+8）**，系统结算：将 Bob 的交易按 6月7日 10% 的比例锁定 $100 待结算返佣。

- 6月8日 00:01，系统判断 Alice 满足 Lv2 \(15%\) 条件，将其等级升至 15%。

- 6月8日 10:00，好友 Bob 再产生 $1000 交易，此时按 15% 计算，应获 $150 返佣。

|时间节点|事件|计算比例|返佣金额|
|---|---|---|---|
|T\-1日 23:00|交易发生|T\-1日 10%|$100|
|T日 00:00（UTC+8）|**收益锁定**|T\-1日 10%|$100（不变）|
|T日 00:01|**等级更新**|升至 15%|\-|
|T日 10:00|交易发生|T日 15%|$150|

|---|---|
| **数据预览** | 列表筛选结果联动汇总；右上角 **统计周期** 控制部分指标 |
| **查询筛选** | UID / 钱包 / 邮箱模糊搜索；邀请等级；结算状态 |
| **用户列表** | 普通用户返佣数据明细，10 条/页；与概览共用 **统计周期** |

#### 统计周期

概览区右上角提供 **1D / 1W / 1M / 3M / ALL**（默认 **ALL**），与列表 **同一控件、同步刷新**。

| 指标 | 是否随周期切换 |
|---|---|
| **直客交易额**、**直客手续费**、**已返佣金额**（概览 + 列表） | **是** |
| **邀请注册用户人数**、**待结算返佣**、**冻结账户**、**冻结账户待返佣金额** | **否**——累计 / 当前快照 |

#### 数据预览 KPI（6 张）

| 顺序 | 卡片 | 口径 |
|---|---|---|
| 1 | **邀请注册用户人数** | 筛选范围内各用户直邀注册人数之和 |
| 2 | **直客交易额** | 周期内直客累计交易额合计 |
| 3 | **已返佣金额** | 周期内已发放返佣合计 |
| 4 | **待结算返佣** | 当前待结算快照合计 |
| 5 | **冻结账户** | 结算状态为冻结的用户数 |
| 6 | **冻结账户待返佣金额** | 冻结用户待结算返佣合计 |

### 列表字段

| 列 | 说明 | 随周期 |
|---|---|---|
| UID | 可复制 | 否 |
| 钱包地址 / 邮箱 | 优先展示邮箱，否则钱包 | 否 |
| 邀请等级 | Lv 0–3，对应 §等级配置表 | 否 |
| 返佣比例 | 当前等级手续费返佣比例 | 否 |
| 邀请好友人数 | 直邀好友总数 | 否 |
| 活跃好友数 | 过去 30 日交易额 ≥ $10,000 的直邀好友数 | 否 |
| 直客交易额 | 直客累计交易额（USDT 折算） | **是** |
| 直客手续费 | 直客累计 gross 手续费 | **是** |
| 已返佣金额 | 已发放至用户账户的返佣 | **是** |
| 待结算返佣 | 已锁定、尚未发放的待结算收益 | 否 |
| 结算状态 | **正常** / **冻结**（冻结时暂停发放，待结算仍可运营回收） | 否 |
| 操作 | **回收待结算**（待结算返佣 > 0 时可用） | 否 |

### 回收待结算

**入口**：列表操作列【回收待结算】

**弹窗字段**：

| 字段 | 类型 | 说明 |
|---|---|---|
| UID | 只读 | 当前行用户 |
| 累计待返佣金额 | 只读 | 等于列表「待结算返佣」 |
| 回收待结算金额 | 必填 · 数字 | 不可超过累计待返佣金额 |
| 回收原因（站内信用） | 必填 · 多行 | 写入用户站内信正文 |

**交互规则**：

- 运营点击【确认】后，系统创建 **待执行回收指令**，挂入 **次日 0:00（UTC+8）** 日结批次队列。
- **当日 0:00 前**（指令所属批次执行前）：允许修改回收金额或撤销指令。
- **过 0 点批次执行后**：回收金额 **不可变更**；系统扣减用户待结算返佣并触发站内信（见下节）。
- 弹窗底部提示文案：**「提交后，回收指令将随次日 0:00（UTC+8）日结批次执行。当日 0:00 前可修改或撤销；过 0 点后将无法变更回收金额，请谨慎填写。」**

### 回收执行 · 站内信任务

#### 触发时机

| 项 | 规则 |
|---|---|
| **任务类型** | `invite_rebate_reclaim_notify` |
| **触发时间** | 运营提交回收指令后，在 **下一个 0:00（UTC+8）** 日结批次中 **执行成功** 时触发（非提交瞬间） |
| **接收人** | 被回收 UID |
| **渠道** | Web / App 消息中心 · 站内信 |
| **幂等** | 同一回收指令 ID 仅发送一次 |

#### 站内信模板

| 项 | 内容 |
|---|---|
| **标题** | 邀请返佣待结算金额已调整 |
| **摘要**（列表预览） | 您的待结算邀请返佣已回收 {reclaim_amount} USDC |
| **正文** | 您好，<br><br>经平台复核，您的邀请返佣待结算金额已作如下调整：<br><br>回收待结算金额：**{reclaim_amount} USDC**<br>回收原因：**{reclaim_reason}**<br>执行时间：**{executed_at}**（UTC+8）<br><br>调整后剩余待结算返佣：**{remaining_pending} USDC**<br><br>如有疑问，请联系在线客服或查看邀请返佣页「待结算收益」说明。 |
| **跳转** | 邀请返佣页（Web / App 各自路由） |

| 占位符 | 说明 |
|---|---|
| `{reclaim_amount}` | 本次实际执行的回收待结算金额（USDC，保留 2 位小数） |
| `{reclaim_reason}` | 运营在回收弹窗填写的「回收原因（站内信用）」 |
| `{executed_at}` | 日结批次执行完成时间，格式 `YYYY-MM-DD HH:mm` |
| `{remaining_pending}` | 回收后用户剩余待结算返佣余额 |

> **说明**：回收指令 **提交时** 不发送站内信；仅在 **0:00 批次执行成功** 后发送上表模板。若批次执行失败（如用户待结算余额不足），不发送站内信，指令进入失败重试 / 人工处理队列。
