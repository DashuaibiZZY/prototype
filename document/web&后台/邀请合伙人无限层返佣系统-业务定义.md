# 邀请合伙人无限层返佣系统 · 业务定义

> **文档导航**：[总览](邀请合伙人无限层返佣系统.md) · [业务定义](邀请合伙人无限层返佣系统-业务定义.md) · [后台管理](邀请合伙人无限层返佣系统-后台管理.md) · [用户合伙人中心（Web）](邀请合伙人无限层返佣系统-用户合伙人中心Web.md) · [用户合伙人中心（App）](邀请合伙人无限层返佣系统-用户合伙人中心App.md)


## 1\.1 核心业务模型

**模型定义：无限级差佣金制**

- 平台为每个一级合伙人设定一个返佣比例上限（运营可在权限后台配置，当前原型演示为 **80%**），该比例即为此合伙人整条业务线的「总佣金包」上限参考。

- 合伙人可以无限层级地发展下级合伙人（平台对**新增发展**设有最多 **10 层**合伙人层级限制，见 §1.4），每一级合伙人的返佣比例由其直属上级设定，且**不得超过**上级自身的比例。

- **级差与合规**：上下级比例**允许相等**（级差 = 0，该上级在该笔交易上级差为 0，属正常配置）。下级返佣比例**不得超过**上级返佣比例。

- 当终端用户（直客或合伙人自营）产生交易手续费时，系统沿邀请链路向上逐级计算级差佣金，直到一级合伙人为止。

**角色定义**

|角色|账号类型|交易时身份|是否参与返佣分配|
|---|---|---|---|
|一级合伙人|Agent|渠道/交易者|是，享受自返佣，并从下级合伙人的级差中获利|
|N级合伙人 \(N≥2\)|Agent|渠道/交易者|是，享受自返佣，并从直属下级合伙人的级差中获利|
|直客|Client|纯交易者|是，为上级合伙人贡献级差的「燃料」，自己不拿返佣|

**核心原则：合伙人自营也参与返佣**

- 合伙人用自己的合伙人账号交易，自己拿走自己返佣比例对应的佣金（自返佣）。

- 同时，他的所有上级依然按级差规则分钱。

## 1\.2 返佣计算规则

### 规则一：自返佣

- 触发条件：代理使用自己的代理账号进行交易并产生手续费。

- 计算：`该代理的返佣比例 × 该笔手续费`

- 拿到钱的人：该代理本人。

### 规则二：直客级差

- 触发条件：直客进行交易并产生手续费。

- 计算：

    - 直客的直属上级代理：拿走自己**全额**返佣比例对应的佣金。

    - 该上级的每一位上级：拿走 `(自己的返佣比例 - 直属下级代理的返佣比例)` 的级差部分。

- 如果上级与直属下级的比例相同，则该上级在这笔直客交易上级差为 0。

### 规则三：代理自营级差

- 触发条件：某代理用自己代理号交易产生手续费。

- 该代理自己先拿走自返佣（规则一）。

- 他的所有上级，按规则二的方式，从他身上计算级差，即 `(上级比例 - 该代理比例) × 该笔手续费`。

### **公式总结：**

- 对任意一笔交易：

    1. 确定交易发起人 `X`（可能是代理或直客）。

    2. 如果 `X` 是代理，`X` 获得 `比例_X × 手续费`。

    3. 沿着 `X` 的上级链路向上遍历，当前上级 `P`：

        - 如果 `P` 是 `X` 的直属上级，`P` 获得 `(比例_P - 比例_X) × 手续费`

        - 否则，`P` 获得 `(比例_P - 比例_直属下级) × 手续费`

    4. 直到一级代理停止。

## 1\.3 返佣结算流程

**整体流程：日结制**

1. **交易数据采集**：系统实时记录每一笔交易的手续费。

2. **每日结算触发**：每日 00:00 \(UTC\+8\)，系统对前一日 00:00:00 至 23:59:59 的所有交易进行结算。

3. **数据同步**：生成用于审查的对账 CSV 包（表 1–4，及建议一并导出的一级比例快照表 2a），进入风控审批队列。

4. **人工审查**：风控或运营人员登录后台「佣金对账与发放」页面，进行四步审计：

    - **总量对账**：用 Platform\_Summary 核对平台总手续费与总返佣预算。

    - **聚合校验**：用 Rebate\_Split\_Detail 的流水表通过 Excel 枢纽分析，反向汇总每个代理应得总金额。

    - **差异比对**：将汇总结果与 System\_Proposed\_Payout 做 VLOOKUP 比对，排查是否存在非零差异。

    - **穿透抽样**：随机抽检一个代理，验证其分账流水是否与 Affiliate\_Map 中的比例关系吻合。

5. **审批执行**：

    - **通过**：风控点击「审核通过并放款」，系统将最终实发金额执行发放。

    - **拒绝**：风控填写拒绝原因，该批次标记为「已拒绝」，打回重算。

6. **数据归档**：所有 CSV 文件和审批记录存档备查。

## 1\.4 返佣比例调整、关系迁移与运营权限

### 运营权限上限与审批

- 每位市场运营在权限配置中设有 **一级合伙人返佣比例上限（%）**（原型演示为 **80%**），页面顶栏展示「权限上限: XX%」。

- **≤ 运营上限** 的比例调整：在返佣树内提交后**即刻生效**（无需审批）。

- **&gt; 运营上限** 的一级绑定或比例调整：须提交审批，流程为 **市场运营提交 → 风控审核 → 老板审批**（风控通过后同步 Lark，老板可在 Lark 或后台通过）；**审批通过后即刻生效**。

- **≤ 运营上限** 的一级合伙人绑定：提交后**即刻生效**（无需审批）。

- **同一批提交中若混合「权限内」与「超上限」修改**：仅超上限项进入审批；权限内修改**自动放弃**（输入框回滚），须先处理超上限申请。

### 两类返佣关系变更动作

后台涉及**返佣归属关系**变更的配置动作有两类：

| 动作 | 入口 | 典型场景 |
|---|---|---|
| **迁移返佣关系** | 侧栏 · 迁移返佣关系 | 将已有用户/代理挂到新的上级之下（仍在平台返佣体系内） |
| **新增一级合伙人** | 合伙人列表 · + 新增一级合伙人 | 将普通用户/直客/N 级代理**升级为一级代理**（新建 L1 伞） |

**用户类型口径**（下文组合表均使用此三分法）：

| 类型 | 定义 |
|---|---|
| **普通用户 / 合伙人直客** | 非合伙人账号；含平台普通用户、某合伙人邀请的直客 |
| **N 级代理** | 合伙人账号且**不是**一级代理（系统 L2–L10） |
| **一级代理** | 合伙人账号且为 L1 根节点 |

### 原上级 · 数据边界（两类动作统一）

无论**迁移**还是**升级为一级合伙人**，对**原上级**（迁移/升级前的直属上级或原归属链）统一适用：

| 维度 | 规则 |
|---|---|
| 返佣人数 | **不变**（历史归属人数不回溯扣减） |
| 交易额 / 返佣 | 变更生效后，该主体及其随迁移/升级带走的伞**不再为原上级产生新的**交易额与返佣贡献 |
| 历史数据 | 变更前已归属的数据**保留** |
| 生效时机 | 无需审批的配置**即刻生效**；须审批的**审批通过后即刻生效** |

**新上级 / 新 L1 伞**侧：迁移后业绩与返佣从生效时刻起按新关系重新累计（周期统计不继承原上级下的数字），详见「迁移后的返佣计算与业绩统计」。

### 返佣关系迁移

**可迁移主体**：一级代理、普通用户/合伙人直客、N 级代理均可发起迁移。

**可作迁移目标**：一级代理、N 级代理、**普通用户（非代理）**均可作为接收方。

**主体 × 目标 · 配置与范围**（核心组合表）：

| 迁移主体 ↓ \ 目标 → | 一级 / N 级代理 | 普通用户（非代理） |
|---|---|---|
| **普通用户 / 合伙人直客** | 须选择迁移后身份：**下级直客**（无需比例）或 **下级代理**（须配置比例 ≤ 上级）；直客随主体一并迁移 | **固定**为下级直客；**不可**选代理身份；**不可**配置返佣比例 |
| **N 级代理** | **整伞迁移**（全部下级代理 + 直客）；须配置迁移主体返佣比例 | **不支持**（代理不可挂到普通用户下级） |
| **一级代理** | **整伞迁移**（L1 伞下全部节点 + 直客）；须配置迁移主体在新上级下的比例 | **不支持** |

**说明**：

- 迁移到**合伙人**下级时，比例须满足：迁移比例 ≤ 目标上级比例。

- 迁移到**普通用户**下级时，仅变更邀请/归属关系，不涉及合伙人返佣比例配置。

- 迁移申请提交后进入 **风控审核**（无需老板审批）；**审批通过后即刻生效**。

- **迁移后的数据统计与返佣归属**见下文「迁移后的返佣计算与业绩统计」及「原上级 · 数据边界」。

#### 新增一级合伙人 · 主体差异

**可升级主体**：普通用户/合伙人直客、N 级代理（**已是一级代理**的不可重复设置）。

| 当前身份 | 升级后范围 | 配置项 |
|---|---|---|
| **普通用户 / 合伙人直客** | 主体本人 + 其**直客**一并挂到新 L1 伞 | 仅配置**一级合伙人返佣比例**；弹窗仅展示**自邀直客人数**（不列明细） |
| **N 级代理** | 主体 + **整伞返佣树**（全部下级代理与直客）挂到新 L1 伞 | 仅配置**一级合伙人返佣比例**；须 **≥ 直属下级合伙人最大返佣**（树内下级比例保留，后续可在返佣树调整） |

升级后对**原上级**的数据边界与「原上级 · 数据边界」一致。返佣比例 **≤ 运营上限** 即刻生效；超上限走一级绑定审批。

### 合伙人层级上限（10 层）与迁移

- 平台对合伙人账号设置**最多 10 层**合伙人层级（L1 为一级合伙人，向下至多 10 层合伙人节点）。

- **用户端（合伙人中心）**：合伙人**新增下级合伙人**时，若会导致链路深度超过 10 层，系统**禁止绑定**新下级。该限制约束的是**新增发展**，不自动裁切已存在的深层节点。

- **迁移返佣关系**：迁移可能使某条业务链在系统内的**实际深度超过 10 层**（例如将较深整伞挂到较浅的上级之下）。迁移完成后：

    - **已存在的深层合伙人节点及其关系保留**，返佣与结算按新关系继续计算；

    - **不因迁移而作废 10 层限制**——限制仍作用于**迁移之后的新增下级**；处于第 10 层及更深处的合伙人，在合伙人中心**不可再发展新的下级合伙人**（与「用户层不允许延续新的下级」一致）。

    - 直客绑定、交易、返佣计算不受「10 层」约束（直客不计入合伙人层数）。

### 迁移后的返佣计算与业绩统计

迁移风控审核通过并生效后，返佣计算**立即**按**新的上级关系**与**新的返佣比例**执行。

**统一规则**：

| 维度 | 规则 |
|---|---|
| 原上级 | 迁移生效后，该伞**不再累计**新的交易额、手续费、返佣贡献；历史已归属数据保留 |
| 新上级 | 迁移生效后，该伞的业绩与返佣贡献从 **0 重新累计**（周期统计不继承原上级下的数字） |
| 返佣计算 | 生效后按新关系与新比例统计、分账 |

**说明**：普通用户迁移仅变更邀请关系；代理用户为**整伞迁移**，伞内全部合伙人节点与直客一并变更上级。

## 1\.5 其他补充

### **活跃用户 / 活跃代理定义**

- 定义为「所选时间周期内，交易额 &gt; 0 的用户或代理」。

- 此指标为**查询时实时计算**，不需要数据落库，不需要维护每日活跃状态表。

- 举例：选择统计周期为「1W」，则统计近 7 天内有过至少一笔交易（交易额 &gt; 0）的用户/代理数量。

- **用户合伙人中心「用户规模」展示口径**：主行展示**交易用户**数（周期内交易额 &gt; 0）；次行灰色小字展示**总用户**数（注册或归属伞内总人数，含未交易者）。**交易用户**数据每天 **UTC+8 0 点**更新；列表表头「用户规模」带虚线下划线，鼠标悬停提示上述更新规则。

### **用户侧佣金与状态展示规则（合伙人中心）**

以下规则仅描述**合伙人登录后**在「佣金管理」及「合伙人管理」中的展示逻辑，与后台批次状态、风控操作对应关系如下：

| 后台 / 系统事实 | 用户侧展示（表格） | 筛选归类 |
|---|---|---|
| 当日批次**等待对账**，佣金尚未放款 | **待审核** | 待结算 |
| 当日批次**已审核通过并放款** | **已发放** | 已结算 |
| 当日批次**已拒绝**（打回重算） | **待审核** | 待结算 |
| 后台在批次**待结算**阶段**调减实发** | **待审核**；返佣主行 = 调减后实发；次行 **违规 −$XX**（虚线，悬停见扣除原因） | 待结算 |
| 上述批次**已审核通过并放款** | **已发放**；返佣与违规扣减展示口径不变 | 已结算 |
| 用户处于**任意冻结状态** | **待审核**；解冻后统一发放变 **已发放** | 待结算 → 已结算 |

### **用户冻结与返佣结算**

当用户账号处于**任意冻结状态**（含部分冻结、账户冻结等，见《[用户风控冻结](用户风控冻结.md)》）时：

| 维度 | 规则 |
|---|---|
| 手续费 | **正常计算**，不因冻结而停止 |
| 返佣统计 | **正常统计**（含直客返佣 + 合伙人级差返佣） |
| 日结算发放 | **暂停发放**，不计入当日应发放批次 |
| 待结算累计 | 冻结期间产生的返佣统一计入**待结算**金额 |
| 解冻后 | **次日 0 点（UTC+8）**对累计待结算金额统一结算发放 |

**普通用户 / 合伙人直客**与**合伙人**均适用上述规则。

**后台合伙人管理列表**展示每位合伙人的**待结算金额**；**结算状态**在冻结期间展示 **冻结待结算**；**冻结状态**列仅在存在冻结时统一展示 **部分冻结** 标签（不论具体冻结项类型），无冻结显示 `—`。

**用户侧**「佣金管理」每日流水在冻结期间对应日期仍展示**待审核**（筛选归类为待结算）；解冻后统一发放时状态变为**已发放**（筛选归类为已结算）（见 §3.5）。

### **净收入（后台指标）**

- 对任意查询根节点（某一级或下级合伙人）：`净收入 = 该伞下净手续费 − 由该伞下交易触发的全部返佣支出`。

- 「全部返佣」包含分给伞内所有合伙人，以及分给伞外上级合伙人的级差（因这些级差均由伞下交易手续费产生）。

- 一级合伙人视角即整条业务线平台留存；下级合伙人视角为「以该合伙人为根的子树」对平台整体的净贡献。
