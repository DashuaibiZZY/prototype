# 合约下单错误拦截与输入限制

**适用页面：**

- Web：[合约交易页](https://dashuaibizzy.github.io/prototype/perp_dex/合约交易.html) · 右侧下单终端
- App：[APP 端合约交易页](https://dashuaibizzy.github.io/prototype/perp_dex/app/合约交易.html) · 底部下单终端

**关联文档：**

- 《合约交易页》§5.4 下单参数与交互框架
- 《APP 端合约交易页》§3.5 下单终端
- 交易对后台配置（价格精度、数量精度、最小成交额、面值等）以产研/后台规则为准

---

## 模块概述

本模块单独描述 **Web / App 合约交易页下单终端** 在前端的 **输入限制** 与 **错误参数拦截** 规则。目标是在用户输入阶段与点击下单按钮时，尽可能提前发现并阻断不合法参数，并以统一的错误提示样式反馈。

**错误提示样式（Web / App 一致）：**

- 阻断类校验失败：底部（App）或右下（Web）**深色 Toast**，左侧红色圆形感叹号图标，文案为一句完整中文说明；约 3 秒后自动消失。
- 开仓超过最大可开：弹出 **「余额不足」** Modal（原充币入口弹窗在此场景下复用，仅改标题，见 §3.4）。

> **原型范围说明：** 标准错误 Toast（价格/数量步进、最小下单、止盈止损方向等）**仅作文档说明，不设独立演示页**。开仓超最大可开 → 「余额不足」弹窗已在 Web / App **合约交易页**原型中实现（见 §3.4）。

## 1. 后台配置项（前端依赖）

以下字段由 **交易对 / 合约后台配置** 下发，前端下单终端启动或切换交易对时加载：

|配置项|说明|示例（BTCUSDC）|
|---|---|---|
|价格精度 `pricePrecision`|价格输入框允许的小数位 / 最小价格刻度|0.1|
|最小步进价格 `priceStep`|提交时价格须为该值的非负整数倍|0.1|
|计价币精度 `quotePrecision`|数量单位为计价币（USDC）时的输入精度|0.1|
|基础币精度 `basePrecision`|数量单位为基础币（BTC）时的输入精度|0.001|
|最小步进数量 `qtyStep`|提交时数量须为该值的非负整数倍|0.001|
|面值代表基础币 `faceValueBase`|该合约最小下单面值（基础币）|0.001 BTC|
|最小成交额 `minNotional`|该合约最小名义成交额（计价币）|62.7 USDC|
|最新成交价 `lastPrice`|校验最小下单、最大可开反推时使用|65432.1|
|最大可开 `maxOpen`|当前方向、杠杆、可用保证金下的最大可开名义价值|1,397.50 USDC|
|最大可平 `maxClose`|当前持仓方向下的最大可平数量|0.35 BTC|

> 精度限制在 **输入时** 约束（禁止输入超精度小数）；步进与最小下单等在 **提交时** 校验。

## 2. 价格输入框

### 2.1 输入精度限制（价格精度）

- **规则：** 关联后台 **价格精度**。例如后台配置 `0.1`，则价格输入框只允许输入至 0.1 粒度（如 `65432.1` 合法，`65432.15` 非法）。
- **时机：** 用户输入过程中实时限制或失焦修正（以实现为准）；非法字符（字母、符号）禁止输入。
- **适用范围：** 限价单价格、止盈止损单触发价 / 委托价（见 §4）、修改委托价格等所有「价格类」输入框。

### 2.2 最小步进价格校验（提交时）

- **规则：** 检查 **最小步进价格** `priceStep` 合理性。提交时校验：输入值必须 ≥ 0，且是步进值的 **非负整数倍**（即 0、步进值、2×步进值……）。
- **失败提示（阻断提交）：**

> 下单价格需为 {步进值} 的倍数，如 0.00、{步进值}、{步进值×2}、{步进值×3}...

- **示例：** `priceStep = 0.1`，输入 `65432.15` → 拦截并提示：`下单价格需为 0.1 的倍数，如 0.00、0.1、0.2、0.3...`

- **市价单：** 无价格输入，跳过本项。

## 3. 数量输入框

### 3.1 输入精度限制

- **规则：** 关联后台 **计价币精度** 或 **基础币精度**。
    - 数量单位为 **计价币（USDC）** 时，精度遵循 `quotePrecision`（例：0.1 → 仅一位小数）。
    - 数量单位为 **基础币（BTC）** 时，精度遵循 `basePrecision`（例：0.001 → 三位小数）。
- **时机：** 输入过程中限制非法字符与超精度小数。

### 3.2 最小下单检查（提交时，按顺序）

前端在提交前 **按下列顺序** 依次检查；**命中第一条即阻断** 并提示，不再继续后续检查。

|顺序|条件|提示文案|
|---|---|---|
|①|计价币下单：输入数量（名义）< `faceValueBase × 参考价`|下单最小数量为 {faceValueBase × 参考价} {计价币名称}|
|②|基础币下单：输入数量 < `faceValueBase`|下单最小数量为 {faceValueBase} {基础币名称}|
|③|计价币下单：输入数量 < `minNotional`|下单最小数量为 {minNotional} {计价币名称}|
|④|基础币下单：输入数量 × 参考价 < `minNotional`|下单最小数量为 {minNotional} {计价币名称}|

**参考价定义：**

- **限价单：** 用户输入的委托价格。
- **市价单：** 最新成交价 `lastPrice`。

**示例（BTCUSDC，`faceValueBase = 0.001`，`lastPrice = 65432.1`，`minNotional = 62.7`）：**

- 计价币模式：① 阈值 = 0.001 × 65432.1 ≈ **65.43 USDC**；若输入 50 USDC → 提示 `下单最小数量为 65.43 USDC`
- 基础币模式：② 阈值 = **0.001 BTC**；若输入 0.0005 BTC → 提示 `下单最小数量为 0.001 BTC`

### 3.3 最小步进数量校验（提交时）

- **规则：** 检查 **最小步进数量** `qtyStep`。提交时校验：输入值必须 ≥ 0，且是步进值的 **非负整数倍**。
- **失败提示（阻断提交）：**

> 下单数量需为 {步进值} 的倍数，如 0.00、{步进值}、{步进值×2}、{步进值×3}...

- **示例：** `qtyStep = 0.001`，输入 `0.0015 BTC` → 拦截。

### 3.4 开仓 · 最大可开检查

- **场景：** 开仓模式；用户输入数量后点击 **开多 / 开空**（或 App「买入开多 / 卖出开空」）。
- **规则：** 当 **输入数量（折算为计价币名义价值）> 下单按钮下方展示的「最大可开 / 可開」金额** 时，**阻断正常下单流程**，弹出 **「余额不足」** Modal。
- **Modal 变更：** 复用原「选择充币方式」弹窗结构与选项（资金划转、充币），**标题由「选择充币方式」改为「余额不足」**。
- **说明：** 下单按钮下方的「最大可开」由后端永续合约公式计算（可用保证金、杠杆、风险限额、已占用仓位等），前端仅展示与比对，不在此文档展开公式细节；计算口径以产研团队规则为准。

**原型验证（Web / App 合约交易页）：**

- Web：[合约交易页](https://dashuaibizzy.github.io/prototype/perp_dex/合约交易.html) — 开仓模式，输入数量大于按钮下方「可開」（演示值 1,397.50 USDC）后点击开多/开空。
- App：[APP 端合约交易页](https://dashuaibizzy.github.io/prototype/perp_dex/app/合约交易.html) — 同上，演示值 1,397.50 USDT。
- 可用余额旁「+」仍打开原标题「选择充币方式」弹窗；仅超最大可开拦截时标题改为「余额不足」。

### 3.5 平仓 · 最大可平修正

- **场景：** 平仓模式；用户输入数量后点击 **平多 / 平空**。
- **规则：** 当 **输入数量 > 下单按钮下方「最大可平 / 可平」** 时：
    - **不阻断** 平仓下单；
    - **不弹出** 余额不足或错误 Toast；
    - 前端将最终提交参数 **修正为最大可平数量** 后继续下单流程（若开启二次确认，确认弹窗内展示修正后的数量）。

## 4. 止盈止损价格检查

本节适用于：

- 下单终端 **「止盈止损」订单类型**（§5.4.3 / App §3.5.3）内的触发价、委托价；
- 限价/市价单 **跟随止盈止损** 勾选区域的止盈价、止损价（§5.7 / App §3.7）。

除下列方向/关系规则外，**触发价与委托价同样适用 §2 的价格精度与最小步进价格校验**。

### 4.1 触发价方向校验

|场景|验证规则|
|---|---|
|开仓 · 双向 · 开多|两个触发价均须 **>** 当前最新成交价|
|开仓 · 双向 · 开空|两个触发价均须 **<** 当前最新成交价|
|开仓 · 单向 · 开多|触发价须 **>** 当前最新成交价|
|开仓 · 单向 · 开空|触发价须 **<** 当前最新成交价|
|平仓 · 双向 · 持多|止盈触发价 **>** 持仓开仓均价；止损触发价 **<** 持仓开仓均价|
|平仓 · 双向 · 持空|止盈触发价 **<** 持仓开仓均价；止损触发价 **> ** 持仓开仓均价|
|平仓 · 单向 · 持多/持空|触发价须 **≠** 持仓开仓均价|

- 所有触发价 **不能等于** 当前最新成交价。
- 失败时阻断提交，Toast 提示具体原因（文案以实现为准，须明确方向冲突）。

### 4.2 委托价校验（仅限价委托时）

|方向|验证规则|
|---|---|
|开多|委托价 **≥** 触发价|
|开空|委托价 **≤** 触发价|
|平多|委托价 **≥** 触发价|
|平空|委托价 **≤** 触发价|

- 委托价须符合 **价格精度** 与 **最小步进价格**（§2）。

### 4.3 数量与其他

- 止盈止损单 **数量** 遵循 §3 全部规则（精度、最小下单、步进、最大可开/可平）。
- 开仓类止盈止损须额外检查 **保证金是否充足**（与 §3.4 最大可开逻辑一致）。
