# 一、Web 端排行榜页

**原型**：[https://dashuaibizzy.github.io/prototype/perp_dex/排行榜.html](https://dashuaibizzy.github.io/prototype/perp_dex/排行榜.html)

## 1\.1 功能定位

展示平台交易者的综合表现排名，支持按多个维度查看与排序。用户可了解自身在全站榜单中的位置，并按 **UID / 钱包 / 邮箱** 搜索其他交易者。

当前支持四个排名维度：

|维度|字段|说明|
|---|---|---|
|收益金额|PnL|统计周期内已实现盈亏金额（USDT）|
|收益率|ROI|统计周期内投资回报率（%）|
|交易额|Volume|统计周期内合约成交额（USDT 名义价值）|
|积分|Points|统计周期内获得的平台积分|

## 1\.7 排行榜表格

页面截图：[**Web · 排行榜表格**](https://raw.githubusercontent.com/DashuaibiZZY/prototype/doc-assets/document/assets/排行榜/web-ranking-table.png)

### 1\.7.1 列定义

|列名|对齐|说明|
|---|---|---|
|排名|居中|当前排序维度下的名次；Top 1–3 使用徽章样式（黑/深灰/浅灰）|
|交易者|左对齐|**UID 加粗**；钱包地址缩写或邮箱位于下方灰色小字（有则展示）|
|收益金额 (PnL)|右对齐|带正负号，盈利绿色，亏损红色|
|收益率 (ROI)|右对齐|百分比，涨绿跌红|
|交易额 (Volume)|右对齐|USDT 名义成交额，大额可用 K/M/B 缩写，琥珀色强调|
|积分|右对齐|整数展示|

### 1\.7.2 排序规则

- 表头 PnL、ROI、交易额、积分均可点击排序。

- 默认排序维度：**收益率 (ROI)** 降序（当前选中列高亮为黑色）。

- 点击列头切换升序/降序；再次点击另一列则切换排序维度。

- 排名列数值随当前排序维度重新计算。

### 1\.7.3 行交互

- 行 hover 浅灰背景。

- Top 3 排名徽章与后续纯数字排名样式区分。

### 1\.7.4 数据展示规则

- PnL：保留两位小数，正数带「+」前缀。

- ROI：保留两位小数，带「%」。

- 交易额：按平台统一金额格式；建议使用 K/M 缩写（如 $128.6M）。

- 积分：千分位分隔，无小数。

# 二、后台管理：排行榜用户数据配置

**原型**：[排行榜用户数据配置](https://dashuaibizzy.github.io/prototype/perp_dex/admin/排行榜后台.html)

> **变更说明（相对旧版「影子配置」）**：已移除影子账户、目标排名区间、生命周期、调度引擎、自动继承等逻辑。运营改为 **直接生成一个新用户**，并为该用户配置榜单指标；后端按 **数据写入时间** 聚合，用户在 Web 端 **7D / 30D** 等周期视图中可见。**无需**运营选择日榜 / 周榜 / 月榜。

## 侧栏结构

后台采用 **ForX Admin 统一侧栏**（见《[后台权限与人员管理](后台权限与角色管理.md)》§3）。

| 侧栏入口 | 页面 |
|---|---|
| 排行榜用户数据配置 | 配置用户列表、筛选与新增/编辑弹窗 |

**权限**（v3）：「排行榜用户数据配置」**写** = 可新增/编辑/停用配置用户；**读** = 仅查看。无敏感组。页面读/写在 **后台人员 → 编辑** 浮层配置。详见《[后台权限与人员管理](后台权限与角色管理.md)》§4.4。原型 **全量展示**。

## 2\.1 功能定位

运营后台用于为排行榜 **创建并配置用户数据**。流程如下：

1. **生成新用户**：系统创建一条后台专用用户（分配 UID、钱包占位或邮箱，标记为运营配置用户）。
2. **选择榜单范围**：全平台，或关联某一 **平台活动** 的子榜单。
3. **填写指标**：按范围展示对应输入项（见 §2.5.4）。
4. **保存**：后端记录 **数据时间**；在 7D / 30D 等统计窗口内可见并参与排名。

本模块支持两类 **榜单范围**：

|榜单范围|说明|
|---|---|
|全平台|三项指标（PnL / ROI / Volume）均可配置，**默认均为 0**|
|平台活动|用户仅参与 **已选活动** 的交易大赛排行榜；**仅展示** 活动已启用的排序维度对应输入框|

### 2\.1.1 活动关联与可选范围

**活动下拉可选条件**（须同时满足）：

|条件|说明|
|---|---|
|活动状态 = 进行中|已结束、未开始等活动 **不出现在** 下拉列表|
|已开启排行榜|活动「交易大赛配置」中排行榜模块为启用状态|

数据来源：活动上架管理系统 · 交易大赛配置。

选择活动后，弹窗 **只读展示** 该活动当前 **排序维度**（交易额 / 收益率 / 收益金额，与活动「榜单配置」中 **已启用** 项一致）。

- 保存时 **不覆盖** 活动本身的排序规则；运营仅填数值。
- 配置指标区 **仅渲染** 活动支持的维度字段，不展示未启用项。

## 2\.2 页面结构

|区域|说明|
|---|---|
|侧边栏|运营模块导航，当前项「排行榜用户数据配置」|
|页头|标题 + 功能说明|
|筛选条|多条件过滤配置列表|
|配置用户列表|表格展示 + 新增入口|
|新增/编辑弹窗|生成用户、榜单范围、配置指标、生效策略|

## 2\.3 筛选条

支持与列表联动筛选，点击「筛选」应用条件，「重置」清空。

|筛选项|说明|
|---|---|
|UID / 钱包 / 邮箱|关键词模糊搜索|
|榜单范围|全部 / 全平台 / 平台活动|
|活动名称|选择「平台活动」后启用|
|配置状态|全部 / 生效中 / 待生效 / 已停用|

## 2\.4 配置用户列表

### 2\.4.1 表头字段

|列名|说明|
|---|---|
|UID / 用户标识|UID 为主；钱包或邮箱为次要行|
|榜单范围|全平台，或「平台活动 + 活动名称」|
|配置指标|按范围展示已配置项（全平台三项；活动仅对应维度）|
|活动排序维度|仅活动范围：只读展示活动启用的排序字段|
|生效状态|生效中 / 待生效 / 已停用|
|数据时间|数据写入时间；次行展示生效策略（立即 / 预约日期）|
|操作|编辑、停用|

### 2\.4.2 状态说明

|状态|含义|
|---|---|
|生效中|数据已按写入时间入库，在对应统计窗口内参与排名|
|待生效|已配置但 **生效日期** 在未来，到期后自动变为生效中|
|已停用|不再参与榜单；历史周期数据保留策略由后端定义|

### 2\.4.3 操作

- **新增配置用户**：打开弹窗，生成用户并填写参数。

- **编辑**：修改指标、生效策略（不可变更已生成的 UID）。

- **停用**：二次确认后标记已停用，从当前及后续周期榜单移除。

### 2\.4.4 列表分页

列表底部统一分页器（见《[后台权限与人员管理](后台权限与角色管理.md)》§3.1）：每页 **10 条**；筛选后回到第 1 页。

## 2\.5 新增/编辑配置用户弹窗

### 2\.5.1 生成用户

|字段|说明|
|---|---|
|生成新用户|点击后系统创建用户并展示 UID（编辑态不可重新生成）|
|用户标识|只读展示 UID；可选展示系统分配的钱包/邮箱占位|

### 2\.5.2 榜单范围

双选项切换：

|选项|行为|
|---|---|
|全平台（默认）|展示 PnL、ROI、Volume 三项输入，**默认值均为 0**|
|平台活动|可搜索下拉选择活动（见下）；只读展示排序维度；**仅展示** 活动支持的指标输入框|

**活动选择控件**：

- 样式：**可搜索下拉框**（点击展开 → 顶部搜索框过滤 → 点击选项选中）。
- 可选列表：**进行中** 且 **已开启排行榜** 的活动；其余活动不可选。
- 保存校验：选择「平台活动」但未选活动时，提示「请选择活动」。

### 2\.5.3 数据时间与统计窗口

**运营侧不提供周期类型选择**（无日榜 / 周榜 / 月榜选项）。

|项|说明|
|---|---|
|数据时间|保存（或预约生效到达）时由后端写入的时间戳|
|统计归属|后端按该时间戳落入 Web 端 **7D / 30D** 等滚动窗口参与聚合与排名|
|可见性|例如配置写入时间为 8 月 25 日，则在 8 月 31 日查看 **7D** 榜单时可见该用户|

- 同一用户在同一榜单范围下 **仅保留一条生效配置**；重复保存为覆盖更新。
- 列表「数据时间」列展示写入时间；预约生效待入库时显示「—」。

### 2\.5.4 配置指标

**全平台**

|字段|类型|默认值|说明|
|---|---|---|---|
|收益金额 (PnL)|数字，USDT|**0**|可正可负|
|收益率 (ROI %)|数字，%|**0**|—|
|交易额 (Volume)|数字，USDT 名义|**0**|—|

- 三项 **均展示**，初始 **均为 0**；运营按需修改后保存。

**平台活动**

|规则|说明|
|---|---|
|字段范围|**仅展示** 该活动在「榜单配置」中 **已启用** 的排序维度对应输入框|
|示例|活动仅启用「交易额」→ 弹窗只出现 Volume 一项|
|未启用维度|不展示、不要求填写、不入库|

- 不参与积分榜配置（积分由积分模块独立统计）。

### 2\.5.5 生效策略

|选项|说明|
|---|---|
|立即生效（默认）|保存后立即写入数据时间并参与当前统计窗口内的排名|
|指定生效日期|选择 **不早于今天** 的日期；保存后为 **待生效**，到达该日 00:00（服务端时区）后写入数据时间并变为 **生效中**|

**产品评估：是否需要「未来生效日」**

|方案|优点|缺点|建议|
|---|---|---|---|
|仅立即生效|实现简单；与日/周/月滚动窗口一致；运营所见即所得|活动上线前无法提前铺榜|适合 **v1 默认**|
|支持未来生效日|可在活动开始前批量预置榜单用户；与活动 go-live 对齐|需待生效状态、定时任务、跨周期边界（如预约在下月 1 日但对应当前月榜）|建议 **v1 保留 UI 与字段，默认可选**；复杂边界由后端文档单列|

**推荐结论**：

1. **默认立即生效**，满足日常调榜与 7D / 30D 窗口对齐。
2. **保留「指定生效日期」** 作为可选能力，用于活动预配置；到期写入 **该日的数据时间**，由后端决定落入哪些统计窗口。
3. 活动子榜仍以 **活动统计规则** 为准（如「报名成功后开始统计」）；配置用户需满足活动侧可见/报名条件。

### 2\.5.6 保存

- 「保存」：校验通过后写入后端。

- 「取消」：关闭弹窗不保存。

## 2\.6 弹层叠放规范（后台）

后台弹窗层级简单，主要为居中配置弹窗；若后续扩展嵌套选择器，须保证后打开层覆盖先打开层，避免选项被遮挡。

# 三、Web 端与后台的数据关系

|项目|Web 排行榜页|后台用户数据配置|
|---|---|---|
|统计维度|PnL、ROI、交易额、积分|后台可配置 PnL、ROI、交易额；积分仍走积分模块|

|交易额口径|周期内合约成交额（USDT）|同左|
|排名更新频率|每 5 分钟（前端展示）|保存后下一刷新周期生效|
|Top 展示上限|前 1,000 名|与真实用户同一规则|

# 四、附录：活动榜单与全平台榜单的区别

**全平台榜单**

- 统计所有符合条件的真实用户 + 后台配置用户。

- Web 端默认展示此榜单。

**平台活动榜单**

- 仅统计已报名该活动的用户 + 绑定该活动的配置用户。

- 活动详情页内的交易大赛排行榜与后台「平台活动」范围对应；**排序维度只读继承活动配置**。

- 同一配置用户在同一活动下仅一套生效配置。
