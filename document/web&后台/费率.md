# 一、VIP 费率业务逻辑

## 1.1 VIP 自然升降级

### 统计口径

- **统计周期**：近 **14 日**合约交易量（USD）。
- **结算时点**：每天 **UTC+8 24:00:00** 取数，按过去 14 日累计交易量匹配 VIP 等级。
- **生效规则**：
  - 交易量**达标**对应档位后，按匹配等级生效费率。
  - 交易量**不达标**时**立即滑档**（降回实际交易量对应的 VIP 等级），不保留历史最高等级。

### VIP 等级与费率表

| VIP 等级 | 14 天交易量门槛（USD） | Maker 费率 | Taker 费率 |
|---|---|---|---|
| VIP 0 | < $5M | 0.015% | 0.045% |
| VIP 1 | ≥ $5M 且 < $25M | 0.013% | 0.039% |
| VIP 2 | ≥ $25M 且 < $100M | 0.010% | 0.034% |
| VIP 3 | ≥ $100M 且 < $500M | 0.006% | 0.029% |
| VIP 4 | ≥ $500M | 0.004% | 0.026% |

### 用户端展示说明

- 用户当前生效的 Maker / Taker 费率，以**实际结算后的等级**为准。
- 升级进度条、距下一等级差额等，均基于近 14 日交易量与上表门槛计算。
- 页面 FAQ 可做简化表述；**以本文档 1.1 节结算规则为准**（每日 UTC+8 24:00:00 取数、不达标立即滑档）。

## 1.2 运营后台配置费率

运营可在后台对用户进行**人工费率干预**，与 VIP 自然升降级并行存在，但优先级更高（见 1.3）。

### 配置方式

| 方式 | 说明 |
|---|---|
| **指定 VIP 等级** | 手动套用 VIP 1–VIP 4 的标准费率（**不含 VIP 0**，VIP 0 仅由交易量自然判定） |
| **自定义费率** | 单独设置 Taker / Maker 费率（列表展示为「自定义」，不显示 VIP 0） |

### 有效期

- 配置时可填写 **有效期天数**（可选）。
- **留空**：表示永久有效，直至运营手动撤销。
- **填写 N 天**：自**审批通过日**起算，第 N 天当日 **24:00:00（UTC+8）** 费率自动失效，用户恢复 VIP 自然升降级。
- 列表中展示「有效期天数」列；未配置运营费率或永久有效时显示 `-`。

### 活动关联

每次提交费率审批须关联活动信息，用于审计与跨模块统计：

| 模式 | 说明 |
|---|---|
| **平台活动** | 从平台活动列表中选择已有活动（展示活动 ID + 活动名称） |
| **自定义活动名** | 手动输入本次活动名称（如「VIP3 大客户专属」「做市商合作」） |

### 生效规则

- 后台配置经**审批通过后**生效（见 1.5）。
- 一旦被运营配置费率，该用户**不再参与 VIP 自然升降级**（冻结在自然升降通道之外，按运营配置费率计费）。
- **撤销运营配置**后，用户恢复按近 14 日交易量匹配 VIP 等级的自然费率（即时生效，无需审批）。
- 若配置了有效期天数，到期自动失效，等效于撤销运营配置。

### 提交审批必填材料

配置费率并提交审批时，须填写：

1. **用户价值证明**（必填）：其他交易所交易量 / VIP 等级等截图（图片格式）
2. **操作备注**（必填）：变更原因及依据
3. **活动信息**（必填）：平台活动或自定义活动名

### 撤销费率设置

- 入口：用户费率设置列表 / 配置抽屉内「撤销费率设置」。
- 条件：仅对当前存在**运营配置**的用户展示。
- 效果：清除人工费率，恢复 VIP 自然升降级；下一笔交易起按自然等级费率计费。
- 须填写操作备注；写入费率操作记录。
- **不走审批流程**，操作即时生效。

## 1.3 费率优先级

同一用户、同一笔合约交易，按以下优先级取费率（高 → 低）：

```
交易对独立配置费率（默认不存在）
        ↓
用户运营配置费率（VIP 等级 / 自定义）
        ↓
VIP 自然等级匹配费率（近 14 日交易量）
```

说明：

- **交易对独立费率**：预留能力，默认全站不启用；若某交易对单独配置，则覆盖用户级与 VIP 级费率。
- **运营配置**：后台人工设置，生效期间屏蔽自然升降级。
- **自然等级**：无运营配置时的默认路径。

---

## 1.4 费率操作审计

费率配置审批、撤销均为敏感操作，所有写操作须记录审计日志：

| 模块 | 日志页面 |
|---|---|
| 费率配置审批申请 / 撤销 | `费率操作记录.html` |

每条日志至少包含：**操作人、操作时间、目标用户（UID / 钱包）、操作类型、变更详情、备注**；费率审批申请另关联价值证明附件存档。

---

## 1.5 四级审批流程（费率配置）

费率配置提交后进入统一四级审批，与体验金发放、积分发放/加成配置共用同一审批引擎。

### 流程步骤

```
市场运营提交申请
        ↓
市场运营交叉审核（须另一位市场运营审核，不可自审自批）
        ↓
风控审核
        ↓
老板审批（后台或 Lark 飞书均可操作）
        ↓
审批通过 → 费率配置生效
```

### 各角色职责

| 步骤 | 角色 | 说明 |
|---|---|---|
| 提交 | 市场运营（费率管理员） | 在配置抽屉填写费率、有效期、活动、证明材料后提交 |
| 交叉审核 | 市场运营（交叉） | 核对活动合理性、用户价值证明、费率幅度 |
| 风控审核 | 风控 | 评估费率优惠对平台收入与套利风险的影响 |
| 老板审批 | 老板 | 最终批准；支持在 Lark 飞书完成，后台同步状态 |

### Lark 联动

- 风控通过后，系统自动将审批单同步至 **Lark 飞书**，老板可在 Lark 中查看并审批。
- 后台审批详情页展示 Lark 审批单号、同步时间、状态，并提供「在 Lark 中查看」链接。
- 老板在后台或 Lark 任一端通过/驳回，两端状态保持一致。

### 审批状态

| 状态 | 说明 |
|---|---|
| 待市场运营交叉审核 | 刚提交，等待交叉审核 |
| 待风控审核 | 交叉审核已通过 |
| 待老板审批 | 风控已通过，已同步 Lark |
| 已通过 | 四级全部通过，费率已生效 |
| 已驳回 | 任一环节驳回，需修改后重新提交 |

### 驳回与重新提交

- 任一环节驳回须填写审批意见。
- 驳回后原申请单状态变为「已驳回」，费率**不生效**。
- 运营须根据驳回意见修改配置后**重新提交**新的审批申请。

## 3.2 费率审批

- 四级审批步骤条，高亮当前步骤。

#### 审批时间线

按时间倒序展示每次操作：提交申请、交叉审核通过/驳回、风控通过/驳回、同步 Lark、老板审批通过/驳回。

#### 审批操作区

当前角色有权审批时展示：

| 操作 | 说明 |
|---|---|
| 通过 | 可选填审批意见，进入下一审批环节 |
| 驳回 | **须填写**审批意见，申请单变为已驳回 |

### 审批通过后的系统行为

1. 审批单状态变为「已通过」。
2. 目标用户的运营费率配置正式生效。
3. 若配置了有效期天数，系统登记到期时间，到期自动恢复自然升降。
4. 费率操作记录中对应条目更新为已生效。

## A. 名词说明

| 名词 | 说明 |
|---|---|
| 自然升降 | 按近 14 日交易量每日 UTC+8 24:00:00 结算的 VIP 等级机制 |
| 运营配置 | 后台人工指定的 VIP 等级或自定义费率，经审批通过后生效 |
| 交易量对应等级 | 仅按 14 日交易量计算的理论 VIP 等级，不代表一定为当前生效等级 |
| 配置等级 | 运营是否介入及介入方式（自然升降 / VIP n / 自定义） |
| 有效期天数 | 运营费率的生效期限，自审批通过日起算，到期自动恢复自然升降 |
| 交叉审核 | 市场运营体系内须由**另一位**市场运营审核，防止单人操作 |
