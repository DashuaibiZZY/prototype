# 交易对额外标签配置

本文档集中说明永续合约**交易对分类**、**Tab 展示优先级**及**额外标签**的后台配置规则与前端取数逻辑。适用于 APP 首页、APP/Web 行情页、APP/Web 合约交易页「选择合约」弹层等场景。

> **说明**：**「自选」（收藏）** 与 **「热门」** 的 Tab/标签入口由**前端写死**，后台**不可**增删、下架或调整其 `priority`；后台仅能配置「热门」标签下的**交易对列表及 rank**，以及自选以外的动态分类标签。

**关联原型**

- [APP 首页](https://dashuaibizzy.github.io/prototype/perp_dex/app/首页.html)
- [APP 行情页](https://dashuaibizzy.github.io/prototype/perp_dex/app/行情.html)
- [APP 合约交易页](https://dashuaibizzy.github.io/prototype/perp_dex/app/合约交易.html)
- [Web 合约交易页](https://dashuaibizzy.github.io/prototype/perp_dex/合约交易.html)

## 1. 交易对基础字段

每个永续合约交易对在后台可配置以下基础展示字段：

| 字段 | 说明 |
|---|---|
| 行业分类标签 | 如「加密货币」「股票」「大宗商品」。决定交易对在行情页/合约页**一级行业 Tab** 的归类；亦用于 APP 首页顶部行情卡片灰色小字展示 |
| 首页顶部显示排序编号 | 整数，默认 `0`。`0` 表示不在首页顶部展示；设置为 `1` 及以上时按编号**正序**排列，**最多展示 4 个**；编号大于 4 的不展示 |

### 1.1 首页顶部卡片选取规则

- 取所有「首页顶部显示排序编号 ≥ 1」的交易对，按编号升序排列，取前 4 个。
- 卡片布局：2 列 × 2 行；展示名称、行业分类标签、迷你 K 线、最新价、24h 涨跌幅。
- 点击卡片跳转该交易对行情详情页。

## 2. Tab 分类与优先级

### 2.0 系统固定项（前端写死，非后台配置）

以下 Tab / 标签由**客户端硬编码**，后台**不提供**增删、下架、`priority` 排序等配置能力：

| 固定项 | 展示名称 | 说明 |
|---|---|---|
| 自选 Tab | 「收藏」/「自选」 | 展示用户自选交易对；数据来源于用户收藏行为，非后台标签配置 |
| 热门 Tab / 标签 | 「热门」 | Tab 入口固定；**仅**其下列表内容由后台 rank 配置（见 §3） |
| 行业筛选条 | 全部 / 数字货币 / 股票 / 大宗商品 | 固定出现在「自选」「热门」Tab 下，选项写死 |

**与后台配置的区别**

- **自选、热门**：前端保证始终存在；运营无法在后台关闭或替换这两个入口。
- **热门列表内容**：后台可配置 rank 排序的交易对；这是 §3 的配置对象，**不是** Tab 本身的配置。
- **新币上线、主流币、AI、TradeFi 等**：属于 §2.3 的**后台可配**额外分类标签，与「热门」不同。

### 2.1 一级行业 Tab

**前端写死（不可后台配置）**

- **自选（收藏）**
- **热门**（APP / Web 合约页均为一级 Tab，位于自选右侧；行业 Tab 下亦可有固定「热门」二级 chip）

**后台可配置 `priority` 的一级 Tab**

- **数字货币**、**股票**、**大宗商品**（及未来扩展的行业 Tab）

| 字段 | 说明 |
|---|---|
| `priority` | 整数，默认 `0`。**数值越小优先级越高**（`0` 为最高）。**仅**适用于 §2.1 中「后台可配置」的行业 Tab；**不适用于**自选、热门 |

**规则**

- 前端渲染 Tab 栏时：**自选、热门**按产品约定的固定顺序占位；其余行业 Tab 按 `priority` **升序**排列。
- 同 `priority` 时，按后台返回顺序稳定排序。
- 后台可下架/新增**行业类** Tab；自选、热门不受影响。

**各端一级 Tab 对照**

| 端 | 一级 Tab 组成 |
|---|---|
| APP 行情 / 合约 | 自选（写死）→ 热门（写死）→ 数字货币 / 股票 / 大宗商品（可配 priority） |
| Web 合约 · 选择合约 | 自选（写死）→ 热门（写死）→ 数字货币 / 股票 / 大宗商品（可配 priority）；与 APP 一级 Tab 顺序一致 |

### 2.2 二级分类 Tab

两类二级 Tab：

| 类型 | 出现位置 | 是否后台可配 | 示例 |
|---|---|---|---|
| 行业筛选 | 「自选」「热门」下 | **否（写死）** | 全部 / 数字货币 / 股票 / 大宗商品 |
| 分类标签 | 「数字货币」「大宗商品」下 | **是** | 新币上线、主流币、AI、TradeFi 等 |
| 固定分类标签 | 「数字货币」「大宗商品」下（可选） | **否（写死）** | **热门**（行业 Tab 下的固定 chip；与一级「热门」列表同源） |

| 字段 | 适用对象 | 说明 |
|---|---|---|
| `priority` | **仅** §2.2 中「后台可配」的分类标签 | 整数，默认 `0`，数值越小越靠前。**热门、行业筛选条不参与** |

**规则**

- 行业筛选条（全部/数字货币/…）：前端写死，顺序固定。
- Web 端「数字货币 → 热门」：热门 chip 写死；列表内容走 §3 rank 配置。
- 后台可配的二级标签：按 `priority` 升序渲染；下架隐藏；新增需配置 `priority`。
- 「股票」一级 Tab 下**不展示**二级分类栏。

### 2.3 额外分类标签（后台可配）

运营可在后台为交易对打标并维护**动态**二级标签，例如「新币上线」「主流币」「AI」「TradeFi」等。

**不属于本节的固定项**：自选、热门、行业筛选条（见 §2.0）。

- 标签可增删；下架后前端隐藏。
- 每个标签可配置 `priority` 控制 Tab 顺序（0 为最高）。
- 交易对可挂载多个额外标签；选中某二级标签时，仅展示带有该标签且归属对应行业的交易对。

## 3. 「热门」标签的特殊排序与填充逻辑

### 3.1 标签属性

- 「热门」Tab/标签入口为**前端写死**（见 §2.0），后台**不能**下架或改名。
- 后台可配置的是「热门」标签下的**交易对列表**及每条记录的 **排序序号（rank）**。
- 前端不同页面从该列表中截取不同数量的交易对展示（见 3.2 节）。
- **仅行情页**在配置数量不足时启用**交易量补齐**（见 3.4 节）；首页、自选推荐等场景不自动补齐。

### 3.2 后台配置规则

1. 管理员可在后台为「热门」标签配置交易对，每条配置包含：
   - 交易对名称
   - 排序序号（`rank`）

2. `rank` 为从 **1** 开始的连续正整数，**不重复**，序号越小展示越靠前。

   例如：

   | 交易对 | rank |
   |---|---|
   | BTC/USDT | 1 |
   | ETH/USDT | 2 |
   | SOL/USDT | 3 |

3. 配置数量不强制，可少于、等于或多于各页面所需数量。

4. 各页面按需从配置列表中截取前 N 个（按 rank 升序）：

   | 页面/场景 | 截取数量 |
   |---|---|
   | APP 首页 · 热门 Tab | 前 **5** 个 |
   | APP 首页 · 热门推荐收藏（无自选时的推荐卡片） | 前 **6** 个 |
   | APP 行情页 · 热门 Tab | 前 **20** 个（不足时可补齐，见 3.4） |
   | APP/Web 合约页 · 热门（一级或二级） | 与行情页热门列表一致或按产品约定同步 |

5. 若后台配置数量**超过**某页面所需数量，则仅截取前 N 个展示，剩余配置保留在后台但不显示。

6. 除行情页 20 条上限的补齐规则外，**首页热门（5）与热门推荐收藏（6）不做任何自动补充**，配置几个展示几个。

### 3.3 前端展示排序逻辑

1. 客户端请求「热门」标签时，获取后台配置的该标签下完整交易对列表。
2. 按 `rank` **升序**排列：`rank 1` 最前，`rank 2` 次之，依此类推。
3. 各页面按 3.2 节表格截取前 N 个。
4. 若配置总数少于页面所需数量（且该页面**不支持补齐**），则展示全部已配置交易对，列表长度相应缩短。
5. 前端**不参与热度算法排序**；顺序完全以后台 `rank` 为准（补齐段除外，见 3.4）。

### 3.4 行情页热门列表 · 不足 20 条时的补齐逻辑

**适用范围**：仅 **APP 行情页 · 热门 Tab**（及与之同步的合约页热门列表，若产品要求一致）。

**触发条件**：按 3.3 节取 rank 排序后的热门配置列表，长度 **< 20**。

**补齐规则**

1. 计算缺口：`缺口数 = 20 - 当前热门配置条数`。
2. 从**全站已上线交易对**中，按 **24h 成交额（USDT 计价）降序** 取候选。
3. **排除**已在热门 rank 列表中的交易对（避免重复）。
4. 按成交量从高到低依次填入，直至列表总数达到 **20**，或候选池耗尽。
5. 补齐段交易对排在 rank 配置段**之后**；补齐段内部按成交量降序，**不参与 rank 混排**。
6. 若全站可选交易对仍不足以凑满 20，则展示「rank 配置 + 已补齐部分」的实际长度，不强求 20。

**与行业筛选的关系**

- 用户在热门 Tab 下选择行业筛选（全部 / 数字货币 / 股票 / 大宗商品）时：
  - 先在完整热门列表（含补齐后的 20 条）上按行业过滤；
  - 补齐候选池的行业属性与交易对「行业分类标签」一致，仅纳入符合当前行业筛选的项（若当前为「全部」则不按行业限制补齐来源）。

**示例**

假设后台热门 rank 配置 8 条（BTC → … → LTC），行情页热门 Tab · 全部：

- 展示顺序：rank 1～8 的 8 个配置项 → 再接成交量第 1～12 的非重复交易对（共 20 条）。

假设仅配置 3 条，行业筛选为「数字货币」：

- 先取 rank 1～3 中属于数字货币的项；
- 再从全站数字货币交易对中按成交量补齐，直至该行业下热门列表达到 20 或候选耗尽。

### 3.5 示例（rank 配置 8 条）

假设后台配置如下：

| 交易对 | rank |
|---|---|
| BTC/USDT | 1 |
| ETH/USDT | 2 |
| SOL/USDT | 3 |
| DOGE/USDT | 4 |
| ADA/USDT | 5 |
| XRP/USDT | 6 |
| DOT/USDT | 7 |
| LTC/USDT | 8 |

各页面展示结果：

- **首页热门（前 5）**  
  BTC/USDT → ETH/USDT → SOL/USDT → DOGE/USDT → ADA/USDT

- **热门推荐收藏（前 6）**  
  BTC/USDT → ETH/USDT → SOL/USDT → DOGE/USDT → ADA/USDT → XRP/USDT

- **行情页（目标 20；配置仅 8 条）**  
  - 前 8 位：rank 1～8 同上  
  - 第 9～20 位：全站 24h 成交量最高的 12 个**未出现在 rank 列表中**的交易对，按成交量降序排列

### 3.6 更新策略

- 后台 rank 或补齐所用成交量数据更新后，客户端在**下次请求**或**切换 Tab** 时生效。
- 前端可对 rank 变化较大的交易对做平滑位置过渡或高亮提醒，避免列表突然跳动。
- rank 段顺序**完全以后台配置为准**；补齐段随成交量变化可能调整顺序，与 rank 段无关。
