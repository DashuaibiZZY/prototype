## 二、#256 功能要点

### 积分加成配置（`#bonus`）

- **单用户 / 批量** 均仅支持 **UID** 关联用户，不再接受钱包 / 邮箱作为录入标识。
- 批量格式：`UID,加成系数`；单次最多 **1000** 条。
- 提交时逐行校验 UID；**有效行进入审批**，无效行弹窗（分页预览、CSV 下载、继续提交有效名单）。
- 确认弹窗「配置人数」仅统计有效行。

### 手动发放积分（`#manual`）

- 多行录入 / 文件上传表头均为 **UID,积分**（兼容 `uid, points`）。
- 校验与弹窗逻辑与加成批量一致；确认弹窗人数 / 总积分仅统计有效行。

### 发放总览明细（`#weekly-detail`）

- 用户标识列由「钱包」改为 **「钱包/邮箱」**：邮箱注册用户展示邮箱，钱包注册用户展示钱包。
- 导出 CSV 表头同步为 **UID,钱包/邮箱,…**。

## 三、#257 功能要点

### 批量区域 amber 提示（积分后台）

- **积分加成 · 批量配置** Tab 下方展示 amber 提示框。
- **手动发放 · 多行录入 / 文件上传** 区域同样展示。
- 文案约定：有效 `200112`、`200445`；无效 `99990001`、`88880002`（用户不存在）。

### 全模块驳回重提

与体验金一致，**所有**后台审批模块（体验金 / 积分 / 费率 / 合伙人）在申请单 **已驳回** 且查看者为 **原申请人** 时：

| 项 | 说明 |
|---|---|
| 保留内容 | 原 payload（名单、配置、附件快照等）**不可修改** |
| 可修改项 | **申请备注** |
| 操作 | 详情页「重新提交审批」→「基于原内容重新提交」→ 生成新 APR 单，审批流从头开始 |

各模块按类型展示不同提示文案（如体验金强调「原名单与卡组」、费率强调「原配置内容」）。
